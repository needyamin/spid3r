Spid3r Documentation / Developer Reference (v1.5.0)

Spid3r Language & Developer Reference

Concise, complete manual for Spid3r v1.5.0 — zero-dependency core VM, YamLLVM native AOT, YamGC memory management, 26 embedded stdlib modules, 254 native builtins, and interactive browser WASM examples.

01. Introduction to Spid3r

Spid3r pairs familiar C/JS-style syntax with memory safety, generics, native BLAS-style linear algebra, M:N channels, and multi-target delivery from one .matrix (or .mt) codebase.

⚡ Spid3r Engine

Four verified backends sharing one front end: AST tree oracle, 60-opcode spvm bytecode VM, YamLLVM (LLVM 23) AOT, and browser wasm32.

🪶 Zero-Dep Core

Compiles with --no-default-features and zero external crates. Three opt-in Cargo features: native, gui, and tls.

🧰 Batteries Included

26 embedded stdlib modules, 254 native builtins (SQLite, PostgreSQL, MySQL, HTTP/WS, JSON/CSV/MsgPack/CBOR/Protobuf), 20+ containers & BLAS.

🔁 Self-Hosted AOT

17-module self-hosted compiler (spid3r-self) reaching a Stage 1→2→3 bit-identical object fixed point across 136 corpus programs.

Component CLI / Artifact Role
Unified Toolchain spid3r · sp Single entry point for running, checking, compiling, building, testing, formatting, LSP, REPL, GUI, and packages.
Native AOT Compiler yamc · spid3r-self Compiles .matrix/.mt directly to native machine code via YamLLVM (LLVM 23.1.0).
Bytecode & VM yamcvm · spvm (spvm_rt) Compiles SHA-256-verified v3 .matrixc chunks and executes them on the pre-decoded 60-opcode VM.
Package Manager spkg Declarative spider.toml dependencies, SHA-256 spider.lock, Ed25519 registries, zero install-time scripts.
Runtime & GC spid3r_lang · YamGC 117 C-ABI AOT trampolines, 254 natives, 16-byte RC values, 30-type cycle collector, and bounded AOT_HEAP arenas.

02. Architecture & Toolchain CLI

One front end feeds every Spid3r target: AST oracle, bytecode VM, LLVM 23 native AOT, and browser WebAssembly.

Stage Module What It Does
1. Lexer src/lexer/mod.rs DFA tokenizer with radix literals (0x/0o/0b), scientific floats, Unicode escapes, and {expr} string interpolation.
2. Parser src/parser/mod.rs Recursive-descent + Pratt parser; recovers up to 25 errors in check/lsp, strict 64-level nesting cap.
3. Semantic src/semantic/mod.rs Type inference, flow-sensitive T? narrowing, exhaustive match, generics/bounds, visibility, E1xxx spans.
4. Lowering src/lower/mod.rs Desugars ??, value-if, for (k, v) in map, destructuring, and sugar before codegen/interpretation.
5. Backends src/vm/ · src/interpreter/ · src/native/ spvm: pre-decoded 16-byte 60-opcode stream; tree: oracle; YamLLVM: LLVM 23 AOT with unboxed containers & split runtime staticlibs.
6. YamGC src/value/gc.rs · src/value/mod.rs 16-byte RC values, 30-type cycle collector, non-blocking REGISTRY pruning, and AOT ValueV2/AOT_HEAP safepoints.

Module Resolution

Every backend resolves import "name" through one shared resolver (spid3r modules --tree shows which won): (1) importing file's folder → (2) SPID3R_PATH → (3) ./stdlib → (4) binary's stdlib/ → (5) enclosing vendor/ → (6) embedded stdlib. Paths with .., drive letters, or absolute roots are rejected everywhere. Imported modules export only public declarations, supporting both import "mod" as m; and selective import { A, B as C } from "mod";.

Tier Source Trust & Guarantee

T5 Native FFI (extern fn) Trusted native C-ABI calls; AOT-only (rejected by spid3r run).

Packages (spid3r / spkg)

A package has a spider.toml and src/. spkg install / spid3r install resolves path, git, local directory, and HTTP(S) registries (SPID3R_REGISTRY / packages.registry; HTTPS requires the tls feature, enabled on Windows), verifies SHA-256 + Ed25519 signatures (packages.trust_pk / registry.pub), unifies diamond semver constraints across workspaces, and never executes install-time build scripts.

Native Compilation (AOT)

spid3r build / yamc (Stage 0) and spid3r-self build (self-hosted) emit standalone machine code via YamLLVM, dead-stripping unused runtime groups and defaulting --release to x86-64-v3 on AVX2 hosts.

Desktop Executables: Custom Icon, No Terminal

Turn any script or GUI into a native windowed app with custom resources and zero VC++ redistributable dependency:

03. Syntax, Variables & Data Types

Clean brace-delimited blocks, semicolon-terminated statements, // and /* ... */ comments, and hybrid static-plus-dynamic typing.

Variables & Constants

Declare mutable bindings with let and immutable compile-time constants with const. Type annotations (: T), nullable types (T?), and unions (int | string) are checked statically when given and inferred otherwise.

⚡ Example: Variables, Constants & Type Annotations

"0.0.0.0") + ":" + string(port) + " tls=" + string(is_secure)); return 0; }

Null Safety ?? (coalesce) · ?. (optional nav) Flow analysis narrows T? to T after if x != null.

06. Control Flow & Loops

if/elif/else works as both a statement and a value-returning expression; loops cover while, C-style for, and collection iteration.

⚡ Example: Conditionals & Value-Position if
fn main() { let marks = 85; let grade = ""; if (marks >= 90) { grade = "A"; } elif (marks >= 80) { grade = "B"; } elif (marks >= 70) { grade = "C"; } else { grade = "F"; } let status = if (marks >= 60) { "Passed" } else { "Failed" }; println("Grade: " + grade + " (" + status + ")"); return 0; }

Loops: while and for

Supports while (cond), C-style for let i = 0; i < n; i += 1, for item in list, for (k, v) in map, plus break and continue.

⚡ Example: C-Style For, While & Map Iteration
fn main() { let sum_evens = 0; for let i = 0; i <= 10; i += 1 { if (i % 2 != 0) { continue; } if (i > 8) { break; } sum_evens += i; } println("Sum evens <= 8: " + string(sum_evens)); let steps = 0; let n = 12; while (n > 1) { if (n % 2 == 0) { n = n / 2; } else { n = 3 * n + 1; } steps += 1; } println("Collatz(12) steps: " + string(steps)); let roles = map("Alice", "Admin", "Bob", "Dev"); for (name, role) in roles { println("{name} -> {role}"); } return 0; }

07. Functions & Closures

First-class functions, default parameter values, mutable lexical closures, and fluent arrow lambdas (x => expr) with .filter, .map, and .reduce.

⚡ Example: Defaults, Closures & Functional Pipelines
fn power(base: int, exp: int = 2) -> int { let res = 1; for let i = 0; i < exp; i += 1 { res *= base; } return res; } fn make_accumulator(start: int) { let total = start; return fn(val: int) { total += val; return total; }; } fn main() { println("power(3): " + string(power(3))); println("power(2, 4): " + string(power(2, 4))); let acc = make_accumulator(100); println("acc(20): " + string(acc(20))); println("acc(15): " + string(acc(15))); let nums = [1, 2, 3, 4, 5, 6]; let squared_evens = nums.filter(x => x % 2 == 0).map(x => x * x); let sum_all = nums.reduce(0, (a, b) => a + b); println("Squared evens: " + string(squared_evens)); println("Sum: " + string(sum_all)); return 0; }

08. Enums, Pattern Matching & Destructuring

Algebraic enum sum types (unit and payload variants) paired with exhaustiveness-checked match arms and boolean guards (if ...).

Destructuring: Unpack lists and tuples directly into bindings with let (a, b) = pair; and loop tuples for (k, v) in map.

⚡ Example: Payload Enums, Match Guards & Destructuring
enum Command { Move(x, y), Rotate(degrees), Stop } fn describe_command(cmd) { return match (cmd) { Move(x, y) if x == 0 and y == 0 => "Hold position", Move(x, y) => "Move to ({x}, {y})", Rotate(deg) => "Rotate {deg} deg", Stop => "Emergency Stop!", _ => "Unknown" }; } fn main() { println(describe_command(Move(10, 20))); println(describe_command(Move(0, 0))); println(describe_command(Stop())); let (x, y) = [100, 200]; let (ip, port, proto) = tuple("10.0.0.1", 443, "https"); println("Point=({x}, {y}) Endpoint={proto}://{ip}:{port}"); return 0; }

09. Error Handling: Exceptions & Option / Result

Use structured try/catch/finally with throw for exceptional control flow, or explicit option (some/none) and result (ok/err) values.

⚡ Example: Try / Catch / Finally & Result
fn parse_positive_int(s: string) { try { let val = int(s); if (val <= 0) { throw "must be positive, got " + string(val); } return ok(val); } catch (e) { return err(string(e)); } finally { println("checked: " + s); } } fn main() { let r1 = parse_positive_int("42"); let r2 = parse_positive_int("-5"); println("r1 ok=" + string(is_ok(r1)) + " val=" + string(r1.unwrap())); println("r2 err=" + string(is_err(r2))); return 0; }

10. Object-Oriented Programming & Generics

Classes with explicit constructors, encapsulation, single inheritance, interfaces with default methods, abstract bases, static members, and monomorphized generics.

Core OOP Rules & Visibility

  • Constructors: Declare public fn new(params) { ... } and instantiate via new ClassName(args).
  • Visibility: Members default to private unless marked public; methods take explicit self.
  • Single Inheritance: Inherit via class Sub extends Base and override methods naturally.
  • super Delegation: Call super(args) in constructors or super.method(...) in overrides.
  • Abstract & Static: abstract class Base / abstract fn work(self); prevent direct instantiation; static fn defines class-level helpers.
⚡ Example: Classes, Visibility & super Delegation
class Animal { public let name; private let energy; public fn new(name: string) { self.name = name; self.energy = 100; } public fn speak(self) -> string { return self.name + " makes a sound"; } public fn play(self, cost: int) { self.energy -= cost; return self.energy; } } class Dog extends Animal { public let breed; public fn new(name: string, breed: string) { super(name); self.breed = breed; } public fn speak(self) -> string { return super.speak() + " -> Woof! (" + self.breed + ")"; } } fn main() { let pet = new Dog("Rex", "Shepherd"); println(pet.speak()); println("Energy left: " + string(pet.play(25))); return 0; }

Interfaces & Polymorphism

Classes conform to structural method contracts using implements InterfaceA, InterfaceB (interfaces may include default method bodies).

⚡ Example: Interfaces & Polymorphism
interface Drawable { fn draw(self) -> string; fn area(self) -> float; } class Circle implements Drawable { public let radius; public fn new(r: float) { self.radius = r; } public fn draw(self) -> string { return "Circle(r=" + string(self.radius) + ")"; } public fn area(self) -> float { return 3.14159 * self.radius * self.radius; } } class Rectangle implements Drawable { public let w; public let h; public fn new(w: float, h: float) { self.w = w; self.h = h; } public fn draw(self) -> string { return "Rect(" + string(self.w) + "x" + string(self.h) + ")"; } public fn area(self) -> float { return self.w * self.h; } } fn main() { let shapes = [new Circle(5.0), new Rectangle(4.0, 6.0)]; for s in shapes { println(s.draw() + " area=" + string(s.area())); } return 0; }

Generics, Constraints & AOT Monomorphization

  • Type Params & Bounds: Multi-parameter generics <K, V> with built-in or interface bounds: <T: Numeric>, Comparable, Printable, or <T: Drawable + Comparable>.
  • Explicit or Inferred: Call sites accept identity<int>(42) and new Box<string>("hi"), or infer types automatically.
  • YamLLVM Unboxing: AOT specializes up to 64 scalar monomorphizations (spid3r_mono_*) and lowers homogeneous list<int> / list<float> to unboxed i64/f64 buffers with loop-hoisted views and BCE.
⚡ Example: Generics & Explicit Type Arguments
class Box<T> { public let value: T; public fn new(v: T) { self.value = v; } public fn get(self) -> T { return self.value; } } fn identity<T>(x: T) -> T { return x; } fn main() { let b = new Box<int>(42); println("Boxed int: " + string(b.get())); println("Generic fn: " + identity<string>("Spid3r")); return 0; }

Method vocabulary & sorting rules — complete reference

Shared & Container Vocabulary

All containers support len, is_empty, and clear. Lists provide mutating (sort, reverse) and non-mutating (sorted, reversed) forms, plus index_of, append, join(sep), for_each, all, and any.

Comparator Sorting & Float Precision

list.sort_by(cmp) and sorted_by(cmp) take fn(a, b) -> int returning negative, zero, or positive. Numeric sorting handles ints and finite floats consistently without NaN corruption.

13. Concurrency, Tasks & Channels

True multi-core M:N worker pool (no GIL, up to 256 workers via spid3r.max_workers) with typed tasks, buffered channels, mutexes, lock-free atomics, and deadlock detection.

Tasks, Join & Synchronization

  • spawn & .join(): let t = spawn fn() { ... }; runs work concurrently and returns a join handle.
  • async / await: Cooperative task syntax yielding clean values across the scheduler.
  • Channels: let ch = channel(); creates an unbounded FIFO queue with send(v), recv(), try_recv(), and close().
  • Mutex & Shared Refs: mutex(init) guards shared state via lock()/unlock(); ref(v) shares mutable boxes safely.
  • Atomic Int: atomic_int(init) (defaults to 0) provides lock-free load(), store(v), add(d), sub(d), and cas(exp, new).
⚡ Example: Spawning Concurrent Tasks & Joining
fn main() { let worker = spawn fn() { let acc = 0; for let i = 1; i <= 100; i += 1 { acc += i; } return acc; }; let atom = atomic_int(7); println("Task sum 1..100: " + string(worker.join())); println("Atomic CAS(7->42): " + string(atom.cas(7, 42)) + ", val=" + string(atom.load())); return 0; }

15. VM Internals, Self-Host, YamGC, WASM & FFI

Inside Spid3r's execution engines, bit-identical self-hosting boundary, cycle-collecting memory model, WebAssembly ABI, and freestanding C interop.

Execution Engines

Engine Entry Implementation
Bytecode VM (spvm) spid3r run · exec 60-opcode chunks compiled to 16-byte pre-decoded records (src/vm/decode.rs) with fused superinstructions & leaf call fast paths.
Tree Oracle --engine tree Reference AST walker (src/interpreter/) and embeddable spid3r_lang::embed::Engine; pins semantic truth.

Self-Hosted Compiler Architecture

selfhost/ hosts a 17-module compiler and dev CLI (spid3r-self) built with zero Cargo/Rust calls after Stage 0 bootstrap, validated bit-identically (Stage 1 → 2 → 3) across the 136-program frozen corpus and coupled cleanly to Rust's 117 C-ABI trampolines + 254 natives.

Bytecode Format, Frames, Optimizer & Policy

A Chunk packs 60 opcodes, constant pools, nested Arc prototypes, and source spans inside a SHA-256-verified v3 .matrixc container (exits 4 on tamper; forward 1.x compatible). Frames preserve lexical module globals and cap recursion at 1,000 catchable frames, while try/catch/finally restores operand-stack depth cleanly.

The optimizer applies oracle-identical constant folding, peepholes, dead-code elimination, and while loop rotation (--no-opt disables optimization + runtime superinstructions cleanly).

Embedders enforce step limits (--budget N) and script-level native capability filters (--sandbox, [security], Engine::deny). Native AOT binaries always execute with full OS user authority.

YamGC: Reference Counting, Cycle Sweep & AOT Arenas

YamGC pairs immediate reference counting on compact 16-byte Value cells (8-byte ThinArcStr + lock-free single-threaded FastMutex) with a rootless mark-sweep cycle collector (triggered every 1,024 tracked allocations across 30 GcTrace impls + REGISTRY pruning) and bounded thread-local ValueV2 / AOT_HEAP frame-root sweeps on Native AOT (gc_collect(), gc_live_cells(), SPID3R_GC=0).
