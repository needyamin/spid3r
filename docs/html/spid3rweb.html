Spid3rWeb Developer Guide

Spid3rWeb is a full-stack web framework written in Spid3r itself: expressive routing, controllers, validation, the SpiderBD template engine, an Active Record ORM on SQLite, sessions and a magic command-line tool. It has no external dependencies. All of it lives in examples/spid3r_web.

2. Quick start

You need the spid3r toolchain. The database uses SQLite through sqlite3.dll / libsqlite3.so (installed next to spid3r, or set SPID3R_SQLITE_PATH).

cd examples/spid3r_web
spid3r magic migrate        # create tables
spid3r magic db:seed        # demo user ada@example.com / secret123
spid3r magic serve          # http://127.0.0.1:8000

magic is a single extensionless file at the project root, so the same spid3r magic <command> works on Windows, Linux and macOS. Run spid3r magic help to list every command.

4. Request lifecycle

  1. Application.handle_request builds a Request and restores the session user from the cookie or bearer token.
  2. GET /css/*, /js/*, /assets/* are served from public/ (paths with .. or \ are refused).
  3. Global middleware runs (CORS by default). A middleware may return a response and stop the chain.
  4. The router matches verb + path. No match → 405 (path exists for another verb, with an Allow header) or 404.
  5. Route middleware runs, then the handler. An uncaught exception becomes a 500 page (JSON under /api/).

5. Routing

Routes are registered on the global Route object inside a function that server.matrix and magic call (register_web_routes()).

import "framework/Router";

public fn register_web_routes() {
    Route.get("/", fn(req) { return home_ctrl.index(req); }).name("home");
    Route.post("/posts", fn(req) { return post_ctrl.store(req); }).middleware("auth");
    Route.get("/posts/:id", fn(req) { return post_ctrl.show(req); });   // :id or {id}
}
MethodPurpose
Route.get / post / put / patch / delete(path, handler)Register a route; returns the entry for chaining
.name("posts.show")Label the route
.middleware("auth") or a listAttach named middleware (auth, cors, logger)
Route.group(map("prefix","/api/v1", "middleware","auth"), fn() { ... })Share a prefix and middleware
req.param("id")Read a path parameter (always a string — use int())

A trailing slash is ignored (/posts/ matches /posts). Browsers only send GET and POST from forms, so the sample app uses POST /posts/:id/update and POST /posts/:id/delete.

6. Controllers

A controller is a plain class whose methods take a Request and return a Response. Generate one with spid3r magic make:controller Invoice.

import "framework/Response";
import "framework/View/BD";
import "framework/Auth/Auth";

public class InvoiceController {
    fn new() {}

    public fn index(self, _req) {
        return view("invoices.index", { "title": "Invoices", "is_auth": Auth.check() });
    }

    public fn apiShow(self, req) {
        let id = int(req.param("id"));
        return json({ "id": id });
    }
}
Prefix unused parameters with _ (_req) to silence unused-parameter warnings.

7. Requests & input

Request merges the JSON body, form body, query string and path parameters. Form and query values are URL-decoded (ada%40example.com becomes ada@example.com).

MemberReturns
req.method, req.pathUpper-case verb and the path without the query string
req.input("k", default)Body → query → path value, or the default
req.string("k", ""), req.int("k", 0)Typed accessors with a fallback
req.has("k"), req.all()Presence check, all body data
req.query("k"), req.param("k")Query-string value, path parameter
req.header("accept", "")Header (names are lower-cased)
req.session_idToken from Authorization: Bearer or the spid3r_session cookie

8. Validation

let v = req.validate({
    "name":     "required|min:2",
    "email":    "required|email",
    "password": "required|min:8|confirmed",
    "role":     "in:admin,editor"
});

if v.fails() {
    return view("auth.register", { "error": v.error_summary() });
}
RuleMeaning
requiredPresent and not empty
emailValid email address
min:n / max:nLength for strings, value for numbers
numeric, integer, alphaType / character class
confirmedMust equal <field>_confirmation
same:field, in:a,b,cEqual to another field, one of a list

The validator offers fails(), passes(), error_messages() (a map of lists), first_error("field"), first(), all_errors() and error_summary(sep).

10. SpiderBD views

Templates live in resources/views as name.bd.html. view("posts.show") loads resources/views/posts/show.bd.html (dots are folders).

@extends('layouts/app')Use a layout
@section('title', 'Short text')Inline section

@section('title', '{{ post.title }} - My Site')

@section('content')
  <h1>{{ post.title }}</h1>
  @if(is_auth)
    <a href="/posts/{{ post.id }}/edit">Edit</a>
  @endif
  @foreach(comments as c)

  @endforeach
@endsection
Always use {{ }} for user-supplied values. Reach for {!! !!} only for HTML you generated yourself.

11. Query builder

DB.table("posts") returns a fluent builder. Values are always bound as parameters.

let rows = DB.table("posts")
    .where("status", "=", "published")
    .orWhere("views_count", ">", 1000)
    .orderBy("id", "DESC")
    .limit(10).offset(20)
    .get();

let one   = DB.table("users").where("email", "=", email).first();
let total = DB.table("posts").count();
let id    = DB.table("posts").insert({ "title": "Hi", "slug": "hi" });
DB.table("posts").where("id", "=", id).update({ "title": "Hello" });
DB.table("posts").where("id", "=", id).delete();

let joined = DB.table("posts")
    .select(["posts.title", "users.name"])
    .innerJoin("users", "users.id", "=", "posts.user_id")
    .get();
MethodNotes
select, where, orWhere, orderBy, limit, offsetChainable
join / innerJoin / leftJoin / rightJoin / crossJoinChainable
get(), first(), find(id), count()List of maps, one map or null, count
insert(map), update(map), delete()insert returns the new id
toSql(), getBindings()Inspect the generated SQL for debugging
DB.select(sql, params), DB.statement(sql, params)Raw SQL with ? placeholders

12. Models

Models are Active Record classes extending Model. They give you an object per row with save, update and delete, and automatic created_at / updated_at.

import "framework/Database/Model";
import "framework/Database/DB";

public class Comment extends Model {
    fn new(attrs = {}) {
        super("comments", ["post_id", "body"], attrs);   // table, fillable, attributes
    }

    public static fn find(id) {
        let row = DB.table("comments").find(id);
        if row == null { return null; }
        return new Comment(row);
    }

    public static fn create(attrs) {
        let c = new Comment(attrs);
        c.save();
        return c;
    }
}

let c = Comment.create({ "post_id": 1, "body": "Nice!" });
c.update({ "body": "Great!" });
println(c.get("body"));
let data = c.to_map();     // pass to a view

Only attributes listed in fillable are written on insert and mass-update. The bundled User and Post models show the full pattern (find, all, create, findByEmail, findBySlug, relations).

13. Migrations & seeders

spid3r magic make:migration create_comments_table
spid3r magic make:model Comment -m        # model + migration
import "framework/Database/Schema";
import "framework/Database/Migration";

public class CreateCommentsTable extends Migration {
    fn new(name: string = "004_create_comments_table") { super(name); }

    public fn up(self) {
        Schema.create("comments", table => {
            table.id();
            table.integer("post_id");
            table.text("body");
            table.string("author").nullable();
            table.string("slug").unique();
            table.timestamps();
        });
    }

    public fn down(self) { Schema.dropIfExists("comments"); }
}

Column types: id, string, text, integer, float, boolean, timestamps. Modifiers: unique(), nullable(), default(v). Columns are NOT NULL unless marked nullable().

Register each new migration in the magic file (an import plus kernel.register_migration(new CreateCommentsTable())). Seeders go in database/seeders/DatabaseSeeder.matrix inside run_database_seeder().

spid3r magic migrate           # run pending migrations
spid3r magic migrate:status    # which have run
spid3r magic migrate:rollback  # undo the last batch
spid3r magic db:seed           # run the seeder

14. Authentication

Passwords are hashed with bcrypt through Hash. Auth is a global facade holding the current request's user.

let hashed = Hash.make("secret123");
Hash.check("secret123", hashed);           // true

if Auth.attempt(email, password) {         // looks the user up, checks the hash, starts a session
    let res = redirect("/posts");
    res.cookie("spid3r_session", Auth.token());
    return res;
}

Auth.check();   Auth.guest();   Auth.user();   Auth.id();   Auth.logout();

Session tokens are 192-bit random values stored in the sessions table (token column). The token is read from the spid3r_session cookie or an Authorization: Bearer <token> header, so browser pages and API clients share one mechanism. Protect a route with .middleware("auth"): browsers are redirected to /login, API/JSON clients get 401.

15. Middleware

A middleware is a class with handle(self, req). Return null to continue, or a response to stop the request.

public class BlockBadBots {
    fn new() {}
    public fn handle(self, req) {
        if req.header("user-agent", "").contains("badbot") {
            return response("Forbidden", 403);
        }
        return null;
    }
}

app.use(new BlockBadBots());                          // global, runs on every request
Route.get("/admin", handler).middleware("auth");      // per route

Built in: CorsMiddleware (answers OPTIONS preflight; global), LoggerMiddleware ("logger"), AuthMiddleware ("auth"). To add a new named middleware, extend resolve_middleware in Application.matrix.

17. Testing

spid3r magic test                                  # framework suites in tests/
SPID3R_PATH=. spid3r run tests/e2e/run_e2e.matrix  # larger end-to-end suite

On PowerShell set the variable first: $env:SPID3R_PATH='.'. You can test an app without a network by building a request map and calling the application directly:

let app = new Application();
register_web_routes();

let res = app.handle_request({ "method": "GET", "path": "/", "headers": {}, "body": "" });
assert_eq(res["status"], 200);

let bad = app.handle_request({ "method": "POST", "path": "/register", "headers": {
    "content-type": "application/x-www-form-urlencoded" }, "body": "email=nope" });
assert_eq(bad["status"], 200);   // form re-rendered with an error

Tests that touch the database should create their own rows and delete them afterwards. Look at tests/test_http_lifecycle.matrix and tests/test_model.matrix for working patterns.

18. Security notes

  • SQL injection: use where() and ? placeholders. Never concatenate user input into SQL.
  • XSS: {{ }} escapes. Avoid {!! !!} for user content.
  • Passwords: only store Hash.make(...) output.
  • Cookies are HttpOnly and SameSite=Lax. Add Secure behind HTTPS (set it in your reverse proxy or extend Response.cookie).
  • Static files are only read from public/; path traversal is rejected.
  • CSRF: state-changing routes are POST with SameSite=Lax cookies. For high-value forms add a per-session token check as middleware.
  • Turn off verbose error pages (debug) in production.

19. Deployment

  1. Copy the project to the server with the spid3r binary and libsqlite3.
  2. Run spid3r magic migrate once, then spid3r run server.matrix 8000 under a process manager (systemd, a Windows service, a container).
  3. Put nginx, Caddy or IIS in front for HTTPS and compression, proxying to 127.0.0.1:8000. The server drains in-flight requests on Ctrl+C / SIGTERM.
  4. Back up database/database.sqlite (and its -wal file) while the app is stopped, or use SQLite's online backup.
