04Method and caveats

  • One process per run. Each sample is a fresh OS process; the harness takes the best of N. Nothing is warmed up across runs, so JIT-less runtimes are not penalised by a cold-start handicap they would not have in a long-lived server.
  • Correctness is part of the measurement. --compare requires the VM and tree engines to print byte-identical output, and every repeat run must reproduce its own output, or the benchmark is reported as failed rather than timed.
  • Micro-benchmarks, not applications. These isolate a loop, a hash table or a call path. They say nothing about startup-to-first-byte for a real program, memory ceiling, or I/O.
  • Absolute numbers are host-specific. The CPU on this machine runs at its base clock under the Balanced power plan; recorded numbers from a turbo-boosted run are ~25–30% higher across every workload and every runtime, including PHP. Compare ratios, not raw milliseconds, across machines.
  • Not measured here: the AOT/native backend (needs LLVM, runs in its own CI job) and the WebAssembly build (see the playground).
