01Enterprise Architecture & Positioning

One unified front end feeds four parity-pinned execution engines — AST oracle, 60-opcode bytecode VM, YamLLVM LLVM 23 AOT compiler, and dependency-free WebAssembly — paired with YamGC deterministic memory reclamation and a zero-dependency core build.

Where Spid3r Excels

  • Zero external core dependencies: Compiles clean via --no-default-features with static CRT linkage on shipped Windows binaries.
  • All-in-one batteries: 26 embedded stdlib modules + 254 native builtins (SQLite, PostgreSQL SCRAM-SHA-256, MySQL 8, HTTP/WS/TLS, JSON/MsgPack/CBOR/Protobuf, BLAS).
  • Fast cold start: Lazy stdlib/tzdata initialization keeps CLI startup under 8.5 ms.

Honest Structural Tradeoffs

  • Checked AOT safety: Preserves signed i64 overflow trapping, safepoint cancellation polling, and mutex-safe containers — unlike unchecked C/Rust raw loops.
  • No speculative JIT yet: V8 / JVM / Rust -O outpace dynamic map/JSON loops where hidden classes or zero-cost structs apply.
  • Un-audited pure-Rust crypto: Passing RFC vectors, awaiting independent audit (R12.1); transport TLS delegates to OS native-tls.

07Methodology, Caveats & JSON Artifact Directory

  • Fresh OS process per sample: Prevents JIT/cache bleed across unrelated workloads; startup cost is calibrated via empty/no-op invocations.
  • Checksum-first acceptance: Runs failing deterministic output or RESULT pin checks are rejected before computing medians.
  • Phase 0 statistical rigor: 9 warmups + 21 measured repeats × 2 passes, requiring MAD/median ≤ 5% and two-pass agreement ≤ 3%.
  • Host-specific absolute times: Compare ratios and dispersions across hosts; micro-benchmarks isolate core loops rather than full I/O service saturation.
