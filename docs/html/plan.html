// server.matrix — Clean, concurrent HTTP Server in Spid3r
import "http";

fn main() {
    let app = http.Server();

    // REST API Route returning JSON
    app.get("/api/status", fn(req, res) {
        return res.json(map(
            "status", "online",
            "engine", "Spid3r Bytecode VM",
            "uptime_ms", now()
        ));
    });

    // Dynamic HTML Route
    app.get("/", fn(req, res) {
        return res.html("<h1>Welcome to Spid3r Web Server</h1>");
    });

    println("🚀 Server listening on http://127.0.0.1:8080");
    app.listen(8080);
    return 0;
}

Step 1: Rust Engine — Exposing TCP Sockets (Zero-Dep)
▼

In src/stdlib/net.rs, create a thread-safe registry for TCP streams and listeners. This uses only standard library std::net:

src/stdlib/net.rs 
use std::net::{TcpListener, TcpStream};
use std::io::{Read, Write};
use std::sync::{Arc, Mutex};
use std::collections::HashMap;

static LISTENERS: Mutex<HashMap<i64, TcpListener>> = Mutex::new(HashMap::new());
static STREAMS: Mutex<HashMap<i64, TcpStream>> = Mutex::new(HashMap::new());

/// Native binding: net_tcp_listen("0.0.0.0", 8080) -> ok(listener_id)
pub fn native_tcp_listen(_ctx: &NativeCtx, args: Vec<Value>) -> Result<Value, String> {
    let host = args[0].as_str()?;
    let port = args[1].as_int()?;
    let listener = TcpListener::bind(format!("{}:{}", host, port))
        .map_err(|e| e.to_string())?;
    let id = allocate_listener_id(listener);
    Ok(Value::Int(id))
}

/// Native binding: net_tcp_accept(listener_id) -> ok(stream_id)
pub fn native_tcp_accept(_ctx: &NativeCtx, args: Vec<Value>) -> Result<Value, String> {
    let id = args[0].as_int()?;
    let mut map = LISTENERS.lock().unwrap();
    let listener = map.get_mut(&id).ok_or("invalid listener id")?;
    let (stream, _) = listener.accept().map_err(|e| e.to_string())?;
    let stream_id = allocate_stream_id(stream);
    Ok(Value::Int(stream_id))
}
Step 2: Spid3r Standard Library — HTTP Module
▼

In stdlib/http.matrix, wrap the low-level socket stream into a modern request/response handler:

stdlib/http.matrix 
class Server {
    private routes;

    public fn constructor() {
        this.routes = map();
    }

    public fn get(path: string, handler: fn) {
        this.routes["GET:" + path] = handler;
    }

    public fn listen(port: int) {
        let listener = net_tcp_listen("0.0.0.0", port);
        while true {
            let stream = net_tcp_accept(listener);
            // Spawn every connection into Spid3r's threaded task scheduler!
            spawn fn() {
                this.handle_client(stream);
            };
        }
    }

    private fn handle_client(stream) {
        let raw = net_tcp_read(stream, 4096);
        let req = parse_request(raw);
        let res = Response(stream);
        let key = req.method + ":" + req.path;
        if this.routes.has(key) {
            this.routes[key](req, res);
        } else {
            res.status(404).send("Not Found");
        }
        net_tcp_close(stream);
    }
}
Step 3: Desktop GUI — Standalone Bundling & Native Dialogs
▼

Currently, spid3r gui file.matrix opens a window, but running a production desktop app requires:

  1. Asset Embedding: Pack HTML/CSS/JS frontend assets into the binary using include_bytes! or a .tar bundle so users don't need raw files on disk.
  2. Custom Protocol: Register spid3r://app/ in wry to serve bundled frontend assets cleanly without CORS/file URL restrictions.
  3. Native Dialogs: Add the rfd (Rusty File Dialogs) crate behind the gui feature to allow opening and saving files via OS native pickers.
Step 4: WebAssembly Target — Running in Browsers Implemented
▼

Spid3r compiles cleanly to wasm32-unknown-unknown with zero external dependencies. The C-ABI bridge (src/wasm.rs) provides high-performance JSON endpoints for evaluating, syntax-checking, and formatting code.

Terminal / Cargo Command 
# 1. Install wasm target
rustup target add wasm32-unknown-unknown

# 2. Build WebAssembly release binary (zero dependencies)
cargo build --target wasm32-unknown-unknown --release --lib --no-default-features

# 3. Output is ready in web/spid3r.wasm
copy target/wasm32-unknown-unknown/release/spid3r.wasm web/spid3r.wasm
