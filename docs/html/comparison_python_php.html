Spid3r vs Python 3.13 vs PHP 8.3 — a measured, verified comparison

Every performance number below was measured on this machine, today, running identical workloads (the project's cross-language benchmark suite) through one harness. Every "cannot do" claim was verified against the source code or reproduced with a probe — no assumptions, no marketing.

Methodology. Windows x64, best of 3 wall-clock runs per benchmark including process startup, same harness for all languages. Versions: Spid3r 1.0.0 (bytecode VM + LLVM AOT "Exec" + tree-walker, release build) · Python 3.13.14 (CPython) · PHP 8.3.33 (CLI, ZTS). Iteration counts match across languages (arith 2M, list 100k, map 20k, closures 20k, strings 30k, methods 200k, json 2k; channels reported in ms). "Iters/sec" = outer loop iterations per second.

2. What Spid3r does have (verified parity or better)

  • Unicode-correct strings — len("héllo") == 5, s[1] == "é" (measured): character-indexed like Python, unlike PHP's byte strings. Plus interpolation, negative indexing.
  • Real closures with correct capture, higher-order methods (map/filter/reduce taking functions — works in all engines, verified).
  • Default parameter values (fn greet(name, greeting = "Hello")) and named arguments (greet(greeting: "Hi", name: "ada")) — both landed 2026-10-22 across all three engines; PHP has defaults, Python has both.
  • Generators, as a library and as syntax — stdlib/gen.matrix gives lazy, composable gen/next/collect/take/map/filter streams (an infinite producer costs nothing until consumed), and compiler-level yield v; is language syntax: a function containing it becomes a generator, lowered by crate::lower into that same library form, so the backends never see yield (verified on both engines — an infinite fib() bounded by 8 yields [0, 1, 1, 2, 3, 5, 8, 13]; §3.3).
  • Memory safety story Python/PHP lack: cycle-collecting GC with weak references (weak()), deep-clone semantics, no GIL — closures/values cross threads safely.
  • LLVM AOT to a standalone native binary + a wasm target — Python/PHP have no equivalent in the standard toolchain (PyInstaller/PHP phar are packaging, not compilation).
  • Zero third-party dependencies in the core; bytecode validator; a 3-engine differential test harness; LSP (hover, diagnostics, symbols, formatting, rename + find-references); formatter; REPL; line debugger; an opcode profiler (run --prof) — in the box.
  • Option/Result error model (some/none/ok/err, ? propagation) and try/catch — PHP has neither natively (exceptions only), Python has neither natively (exceptions only).
  • A built-in test framework (stdlib/assert.matrix: eq/ne/near/contains/throws + a done() exit-code protocol) — pytest-shaped, no third-party install.
  • Batteries that matter for its size: SQLite driver, regex, JSON, CSV, TOML/XML/YAML (parse + write), MessagePack/CBOR/protobuf, gzip/zlib/DEFLATE and .zip with CRC-32 and Adler-32, PNG/WAV/PDF, semver, UUID v4, hex/base32/base64, datetime (UTC), SHA-256/HMAC, PBKDF2 + scrypt + bcrypt + Argon2 + secure_compare, chr/ord, process spawn, a web micro-framework (routing, cookies, JWT sign/verify, templates, form/query parsing — stdlib/web.matrix), and a numeric/data stack written in Spid3r: vector/matrix linear algebra, fft, stats with the distribution family, ml, dataframe, mathx (ANOVA, Mann-Whitney, KS, interpolation, sparse), plus exact bigint/decimal/rational/complex (§3.5 has the honest limits of that stack).
  • Threads with real parallelism (spawn on an OS-thread pool, channels, mutexes) — PHP has no built-in threads (ZTS aside); Python has the GIL (free-threading is new/experimental in 3.13).

3. What Spid3r cannot do today (verified) — vs Python and PHP

3.1 Platform & I/O — the hardest gaps

  • FIXEDEvented I/O. tcp_poll([conns], timeout_ms) is backed by the platform readiness call — WSAPoll on Windows, poll(2) on Unix, declared by hand so the zero-dependency rule holds — so the OS wakes the caller the moment a socket is ready (measured: a 5-second wait returns in ~60 ms when data arrives). stdlib/event.matrix is a working event loop over it (register callbacks; one task dispatches any number of connections), which is the asyncio/ReactPHP role. Verified on both engines, including a two-client echo multiplexed by a single task. What remains, stated precisely: async fn and await exist and work, but await is a synchronous join of a task or channel — there is no suspension-based executor, so concurrency is still one scheduler task per unit of work (fine for hundreds/thousands of connections, not for 100k fibers). Python's asyncio is a true suspension runtime; PHP's Fibers likewise. (HTTPS closed earlier the same day: the opt-in tls feature adds HTTPS to http_fetch via native-tls + the OS certificate store, verified with a real fetch of https://example.com; the zero-dependency default build is unchanged.)
  • FIXEDWebSockets and multicast — shipped 2026-10-22: the full RFC 6455 client+server (ws_connect with accept-key verification, ws_accept, masked frames, auto-pong, fragment reassembly, close handshake) and IPv4 multicast (udp_join_multicast/leave_multicast/set_multicast_ttl/set_broadcast). Verified on both engines with a loopback echo and a real group delivery. Only ws://: wss:// needs the opt-in tls feature (the zero-dependency default build stays as-is).
  • FIXEDTask cancellation — task.cancel() shipped 2026-10-22 and works identically on all three engines: a runaway compute task stops at its next cancellation point (per-statement in the tree engine, every 2048 instructions in the VM, a per-loop counter poll in AOT code, and a time-sliced channel wait), a task blocked on an empty channel wakes up, join() raises "task cancelled", status() reports "cancelled", and cancelling a finished task is a no-op. Structured concurrency (scoped tasks) is a separate, still-open design item.

3.2 Numbers & data types

  • FIXEDSilent integer overflow. The worst of the three was a correctness bug, not a missing feature: 9223372036854775807 + 1 used to wrap to -9223372036854775808 with exit 0. It is now a runtime error (integer overflow: 9223372036854775807 + 1) in all three engines — Python raises, PHP converts to float; nobody silently corrupts. The VM's fast-path superinstructions fall through to the checked path, so the common case pays one predictable branch.
  • FIXEDArbitrary-precision integers — stdlib/bigint.matrix: add/sub/mul/divmod/pow/cmp/neg/abs over base-10⁴ limbs, verified against Python for 2^128, 25!, and a 30-digit product/quotient. It is a library, not literal syntax: int stays 64-bit, so you opt in with bi.from_string(...). O(n²) multiplication, schoolbook division — correct, not fast. These three libraries run on the tree and VM engines; the native backend still rejects import ... as alias, so an AOT build of a program using them is refused with a clear diagnostic (pre-existing limitation, unrelated to the libraries).
  • FIXEDDecimal (exact money math) — stdlib/decimal.matrix: {units, scale} over bigint, so 0.10 + 0.20 is exactly 0.30, division takes an explicit precision, and round is half-away-from-zero. This is Python's decimal role; PHP's bcmath equivalent.
  • FIXEDComplex numbers — stdlib/complex.matrix: add/sub/mul/div/conj/abs/arg/polar/from_polar over {re, im}. Python has a builtin type; this is a library with the same arithmetic.
  • FIXEDOperator overloading — a language feature, not a library trick: any value carrying a callable __add__/__sub__/__mul__/__div__ (a map or a class instance) handles the operator, so 0.10 + 0.20, x * y on bigints, and z1 * z2 on complex numbers all read naturally. Unary minus and the reflected forms (__neg__, __radd__, __rsub__, __rmul__, __rdiv__) work too, so -n and 2 * n on a bigint are ordinary expressions rather than bi.neg(n)/bi.from_int(2) * n. Dunder keys are hidden from display. Works on the tree and VM engines (the native backend reports its usual unsupported-feature diagnostic).
  • FIXEDBig-integer literals and exact rationals. A trailing n makes a literal arbitrary-precision (123456789012345678901234567890n, digits preserved verbatim, auto-importing bigint), and stdlib/rational.matrix provides exact fractions (1/3 + 1/6 == 1/2, reduced, with operators) — the fractions.Fraction role. decimal stays a call (dec.from_string("0.10")) exactly like Python's Decimal("0.10"), so the shape matches. Values also display as their numeric form (0.10, 1/2, -7.0+24.0i) rather than as internal maps. Two limits found by probing this bullet, both now stated instead of assumed: a bigint accepts a plain int or decimal string on either side of + - * / (100n * 2, 100n + "41"), and since the reflected operators and __neg__ shipped, 2 * n, 1 - n and -7n are ordinary expressions too (verified on both engines). The mixed-operand and neg/abs cases used to crash inside the library and are covered by bigint_mixed_operands_on_both_engines. The remaining numeric gap is not these types but scale: 1-D vector and 2-D matrix exist with elementwise/matmul/solve/inverse/det, but there is no N-d array, no broadcasting and no BLAS (§3.5).

3.3 Language constructs (all verified by probe/source)

  • FIXEDGenerators. yield v; is language syntax now: a function containing yield becomes a generator, and crate::lower rewrites it into the stdlib/gen.matrix form (the body moves into an emit closure; the function returns the generator). Lazy consumption is real — an infinite fib() bounded by take(6) is verified on both engines. Cost model, stated plainly: one scheduler task per live generator, so thousands are fine and hundreds of thousands want a suspension-based executor (still a DESIGN item). Python's yield suspends a frame; this lowers to tasks — same semantics, different cost.
  • FIXEDDefault parameter values — fn f(x, limit = 10), trailing-only constants, filled at the callee in all three engines (2026-10-22).
  • FIXEDNamed arguments — f(host: "b.io", secure: true) on direct calls, constructors, and super; method calls reject them with a precise diagnostic (documented v1 limit, 2026-10-22).
  • FIXEDAbstract classes — abstract class Shape { abstract fn area(self); }: an abstract class cannot be instantiated, and the checker rejects a concrete subclass that leaves an inherited abstract method unimplemented (both diagnostics verified). The template-method pattern works: a concrete method may call the abstract one. Traits/mixins remain absent — interfaces cover the "contract" role; PHP-style horizontal code reuse does not exist.
  • FIXEDGenerics (erased) — class Box<T> and fn first<T>(xs) -> T parse, and the type parameters are erased: Spid3r is dynamically typed, so a parameter documents intent rather than driving static checks. That is the correct model for this language (the same reason Python's type hints are not enforced at runtime), but it is not Java/C# generics — no specialization, no static constraint on T.
  • FIXEDOperator overloading — a value carrying a callable __add__/__sub__/__mul__/__div__, or a reflected __radd__/__rsub__/__rmul__/__rdiv__ or a __neg__ (a map or a class instance) handles the operator (§3.2).
  • FIXEDDecorators — @memo and @cache(10) before a function or class, applied bottom-up exactly like Python: the parser desugars to f = dec(f) after the declaration, so a decorator is just a function taking the original and returning a replacement (memoization verified). Macros and compile-time reflection/introspection remain absent — no getattr/type()-style runtime introspection.
  • FIXEDRich interpolation holes — a hole takes any expression, not just a name or field path: "len={len(xs)}", "sum={a + b}", "{name.upper()}". The hole's text is captured by the lexer (nested braces and quoted strings tracked) and compiled by the parser; a hole that does not parse stays literal text, so prose like "{not a hole}" and template syntax {{ user }} are unaffected, as are format specs ({:.2f}) and JSON-looking text ({"a": 1}).

3.4 Ecosystem — the biggest realistic difference

  • NORemote package registry. spid3r install works from a local registry/vendor dir only; no HTTP registry, no package signing, no transitive resolution. Python: ~600k packages on PyPI one pip install away; PHP: Packagist/Composer. Spid3r: zero third-party packages installable from anywhere. Everything you want — requests, numpy, pandas, pillow, lxml, symfony, laravel, SQLAlchemy, pytest — you would have to write yourself. This is the single largest gap.
  • PARTIALDatabase breadth — four drivers now ship, all zero-dependency and all speaking the real wire protocols: Redis (RESP2), PostgreSQL (protocol v3: trust, cleartext, MD5 and SCRAM-SHA-256 auth, simple query, text rows typed by OID), MySQL/MariaDB (protocol 41, mysql_native_password plus the caching_sha2_password fast path, COM_QUERY resultsets) and the pre-existing SQLite. Each was tested against a protocol-accurate server that verifies the client's auth maths with hashlib/hmac (tools/db_test_servers.py, driven by tests/db_drivers.rs). Still absent: MongoDB, TLS (sslmode is refused rather than silently downgraded), caching_sha2_password full auth (needs RSA/TLS), prepared statements, and connection pooling.
  • PARTIALWeb-serving stack — the pieces ship now; what is still missing is the ecosystem around them, not the mechanisms. Multipart uploads: multipart_parse is a native (an uploaded PNG is not text — req["body"] has been through a lossy UTF-8 decode, so requests now carry body_bytes too), with stdlib/multipart.matrix on top: multipart_form, multipart_file, multipart_save and a filename sanitiser that strips paths and Windows-illegal characters. Sessions: stdlib/session.matrix is a server-side store — opaque IDs from the OS CSPRNG (random_bytes, not the xorshift behind random_int), an HMAC-signed cookie checked with secure_compare, absolute and idle timeouts, ID rotation on login (session-fixation defence), revocation that actually revokes, flash data, and an optional file-backed store. Middleware: stdlib/middleware.matrix provides recover, request-id, access-log, security headers, CORS with real preflight, gzip, ETag/304, body limits, Basic auth and a rate limiter, composable around a new fn(req, next) contract (app.use_next) so a middleware can rewrite the response. Server: http.serve_listener does keep-alive with an idle timeout, request and body limits, error isolation (a throwing handler is a 500, not a dropped connection), an access log, and a graceful drain on Ctrl+C/SIGTERM via a new shutdown_requested native — the same loop now backs both HttpServer and WebApp, where before each had its own one-request-per-connection loop. FastCGI: stdlib/fastcgi.matrix is a real FastCGI responder (records, PARAMS name-value pairs, STDIN/STDOUT, END_REQUEST, keep-connection), so nginx or Apache can front an app exactly the way php-fpm is fronted. The WSGI analogue is the app itself: fn(req) -> response is what both the HTTP server and the responder drive, so there is no adapter layer to write. Still missing: no third-party middleware or template ecosystem (that is a package registry problem, §3.4), no WebSocket/SSE integration in the framework, no HTTP/2, no built-in multipart streaming (a body is buffered up to the 8 MiB limit before parsing), and sessions are single-process: a file-backed store assumes one writer, and a multi-server deployment needs a database.

3.5 Standard library gaps (state after the 2026-10-24 implementation pass)

Each line was checked by running it on the tree and VM engines, and the interoperable formats were checked against an outside implementation (CPython's zlib/zipfile/hashlib, OpenSSL's ARGON2*, the OpenBSD bcrypt vectors, a from-scratch Python PNG decoder). The tag is the verdict; the detail is what you would actually hit.

  • CLOSEDCompression. deflate/inflate, gzip_compress/gunzip, zlib_compress/unzlib, zip_create/zip_read/zip_list, plus crc32/adler32 — all from the RFCs, no dependency. The decoder handles stored, fixed-Huffman and dynamic-Huffman blocks; the encoder emits LZ77 tokens and picks whichever of fixed or dynamic Huffman is smaller (so it no longer loses to zlib: 23000 bytes of text → 140 bytes against zlib level 9's 139). Interop was tested both ways: Spid3r decodes CPython's level-9 streams (empty, one byte, text, 100 KB of random bytes, all 256 byte values — every SHA-256 matched), CPython's zipfile reads Spid3r archives with testzip() clean, and Spid3r reads Python-written archives.
  • CLOSEDSerialization beyond JSON/CSV. TOML (parse + write), XML (parse + write: declaration, comments, CDATA, entities, both quote styles; DTDs rejected rather than half-expanded), YAML (parse + write: block maps and sequences, nested blocks, - key: value, flow collections, quoted and block scalars), plus MessagePack, CBOR and the protocol-buffers wire format (msgpack_encode/decode, cbor_encode/decode, pb_encode/decode — the canonical field-1 varint-150 message encodes to 08 96 01). Not there: a .proto compiler (this is the wire codec a generated stub would emit), XML Schema validation, and YAML anchors/tags — those are rejected, not silently ignored.
  • PARTIALEmail/SMTP, FTP, SSH — all three clients ship now, and each was tested against a protocol-accurate peer rather than a mock of itself. stdlib/smtp.matrix is a real ESMTP client (RFC 5321: EHLO with capability parsing and a HELO fallback, AUTH PLAIN/LOGIN including the no-initial-response path, MAIL/RCPT/DATA, dot-stuffing, RSET after a failed transaction) plus an RFC 5322 builder: multipart/alternative and multipart/mixed, 7bit or base64 parts chosen per body, RFC 2047 encoded-word subjects folded on character boundaries, RFC 2231 filenames, Bcc in the envelope only, and header injection rejected instead of escaped. stdlib/ftp.matrix speaks RFC 959 with EPSV/PASV data connections, MLSD/LIST/NLST parsing (Unix and DOS listing shapes), and RETR/STOR/SIZE/CWD/PWD/MKD/RMD/DELE/RNFR-RNTO. Its binary transfers go through a new native pair, tcp_recv_to_file/tcp_send_file, because tcp_read is UTF-8 lossy — a script-level read loop would silently corrupt any download, which is the sort of bug that ships. Both are exercised on the tree and VM engines against a fake server written in Spid3r (tests/mail_ftp_tests.rs), and the FTP test pushes 0x00/0x80/0xC8/0xFF through RETR and STOR and compares the bytes. The honest limit: no TLS. There is still no TLS stream native — http_fetch builds one internally for https:// — so neither client can negotiate STARTTLS or AUTH TLS. Both therefore refuse credentials on a cleartext channel unless the caller passes allow_plaintext_auth: true, and smtp_connect(..., map("tls", true)) fails with an explanation instead of downgrading. That makes them clients for a local relay or a test server, not for a public provider. SSH is deliberately not reimplemented. stdlib/ssh.matrix drives the system OpenSSH client through exec_capture (ssh_exec, sftp_get/put/batch/mkdir/remove/list) and adds what scripts get wrong: a validated argv with no shell anywhere, a fixed option whitelist that cannot express ProxyCommand (local command execution), rejection of hosts starting with - or carrying @, BatchMode=yes so a missing key fails instead of hanging on a prompt, and StrictHostKeyChecking=yes unless an explicit, validated value says otherwise. Writing curve25519/ed25519/ChaCha20-Poly1305 to avoid a process spawn would be exactly the half-finished client this document used to warn about.
  • CLOSEDPassword hashing. pbkdf2_sha256, scrypt (RFC 7914), bcrypt_hash/bcrypt_verify (Blowfish tables regenerated from the hex digits of pi and asserted against the published constants; two OpenBSD vectors reproduce exactly) and argon2 with all three variants (d/i/id, matching OpenSSL byte for byte), plus secure_compare for timing-safe digest comparison.
  • PARTIALImage/audio/media, PDF. PNG encodes and decodes: colour types 0/2/3/4/6, all five row filters, Adam7 interlacing, 16-bit reduced to 8 — verified by decoding PNGs built by an independent Python encoder and by decoding Spid3r's output with an independent Python decoder. WAV reads and writes PCM (8/16/24/32-bit). PDF writes multi-page Helvetica documents with a correct xref. Missing: JPEG (a baseline decoder is its own project) and any audio codec beyond PCM.
  • PARTIALTime zones, Unicode normalization, locale — the first two now ship, both from generated tables and both verified against CPython. Time zones: stdlib/tz.matrix over a 208 KB generated blob (tools/gen_tzdata.py) — 343 canonical zones plus 255 links from tzdata 2026e, transitions authoritative 1900–2100, with tz_format, tz_parts, tz_from_parts, tz_iso, tz_day_bounds (a DST day really is 23 or 25 hours) and tz_add_days (keeps the wall clock across a transition). The generator does not copy TZif: modern builds are slim — Europe/Berlin's last explicit transition is 1996 — so it parses the POSIX TZ footer and synthesises every transition to 2100, then checks all 343 zones against CPython's zoneinfo at every transition ±1 s and on a monthly sweep of the whole range. format_datetime gained %z/%Z/%a/%A/%b/%B/%j/%e/%I/%p/%u. Unicode: stdlib/unicode.matrix implements UAX #15 NFC/NFD/NFKC/NFKD (recursive decomposition, canonical ordering, composition with the blocking rule, algorithmic Hangul) and full case folding, over tables generated from UCD 15.1 by tools/gen_unicode_tables.py. The example this document used to cite now behaves: "e" + U+0301 and precomposed "é" compare equal (unicode_equal), unicode_caseless_equal("STRASSE", "straße") is true, and unicode_nfkc("ﬁ") == "fi". Comparison exposes the three UTS #10 strengths — primary (case- and accent-insensitive), secondary (accent-sensitive) and tertiary (exact) — with sort keys and a stable unicode_sort. The honest limits: this is not UCA/DUCET. Within a level the order is code points, so é sorts after z, and there is no per-locale tailoring (Swedish å/ä/ö after z, German phonebook ö = oe). That needs the multi-megabyte DUCET table, so it is stated rather than approximated. There is also no CLDR: month and weekday names are English and per-locale number/date patterns do not exist. Grapheme counting is mark-based (unicode_cluster_len), not UAX #29, so an emoji ZWJ sequence counts as several characters.
  • PARTIALMath/science stack. 1-D vector, 2-D matrix, fft/ifft, stats (descriptive through t-test, chi-square and the distribution family), ml (linear/logistic, kNN, k-means, PCA, metrics), dataframe, exact bigint/decimal/rational/complex, and mathx (ANOVA, Mann-Whitney, Kolmogorov-Smirnov, interpolation, moving average, convolution, CSR sparse matrices, exponential/binomial/Poisson draws, shuffle/choice). Operator overloading now includes unary minus and reflected operators, so -n, 2 * n and 1 - n all work on a bigint. Still missing: N-d arrays, broadcasting, fancy indexing, and BLAS-class kernels — the numeric stack is 1-D/2-D and scalar-loop bound.

Found while building this: the bytecode VM miscompiles not (A or B) when the right operand has to be evaluated — the tree engine is right and the VM is wrong. It is worked around in stdlib/yaml.matrix (bind the logical to a local first) and written up in docs/VM_NOTES.md; fixing it belongs in src/vm/compiler.rs with a new row in tests/engine_matrix.rs.

3.6 Tooling gaps (state after the 2026-10-24 passes)

  • CLOSEDLSP semantic tokens / code actions — both shipped. textDocument/semanticTokens/full answers with the standard 16-type legend, delta-encoded: keywords and literals from the token kind, identifiers classified through the same symbol index hover uses (function / class / method / parameter / variable / property / enumMember), comments from the lexer's side-channel, and declaration/readonly modifiers. Two details that took real work: a parameter's index extent is its function body, so the token in the signature resolves through a declaration-name fallback; and fn new() lexes as a keyword, so a keyword spelling that names a declaration is coloured as that declaration. textDocument/codeAction offers the three fixes the checker can prove: rename an unused binding to _name (the documented "intentionally unused" spelling), delete an unused import line, and add a missing import "x"; when the unknown name is a stdlib module. Still absent: incremental and range-based token sync (full only), and any action that would need judgement — a quick fix that guesses is worse than none.
  • CLOSEDTest tooling — the three named gaps are filled. Mocking: stdlib/mock.matrix — stub/stub_throws for inert doubles, mock0..mock3/mock_list for recording ones (a closure cannot carry named state and there is no arguments object, so a mock is a {call, log} handle and the constructors are arity-specific), with mock_called_with, mock_assert_called_once and friends. Fixtures: stdlib/testkit.matrix — a suite with a fresh temp directory per case, before_each/after_each, failure isolation (one throwing case does not stop the run), per-case timing, skip, and a done() exit code, plus with_tmpdir which cleans up even when the body throws. Coverage: spid3r run --engine vm --coverage [--coverage-out lcov.info] — per-line hit counts collected in the dispatch loop (the VM already stores a span per instruction), a percentage table on stderr and standard LCOV for genhtml/Codecov. The denominator is the set of lines some instruction was emitted for, so comments and blank lines do not dilute the number. Still absent: branch coverage, coverage on the tree engine (no instruction stream to hook — the flag refuses rather than lying), parallel test execution, a --filter, and JUnit XML output.
  • CLOSEDInteractive debugging depth — the line debugger gained the three things it was missing. print <expr> evaluates in the paused frame; watch <expr> re-evaluates at every pause (and validates at registration, so a broken watch fails once, not at every stop); repl evaluates expressions until an empty line or a debugger command. That needed real debug info: the compiler now records each local's name, slot and live byte range, so locals prints nums = [1, 2, 3, 4] instead of [0] (stack), and a name that has gone out of scope fails instead of showing a stale slot. Evaluation reuses the tree interpreter with the live locals bound as globals — no second evaluator to keep in sync with the language. Still absent: DAP (so no VS Code attach — this is a stdin debugger, scripted with --commands), conditional breakpoints, and debugging the tree engine.

4. Bottom line (no sugar-coating)

Spid3r is a fast (PHP-class VM, and now a competitive AOT), safe, self-contained language with a genuinely nice core — unicode strings, closures, threads without a GIL, default parameters, named arguments, generators, AOT+wasm targets, and an error model PHP/Python don't have. What changed since the previous revision: HTTPS works (opt-in), and the library gaps closed in bulk — gzip/zlib/DEFLATE and .zip, TOML/XML/YAML parse+write, MessagePack/CBOR/protobuf, bcrypt and Argon2 (d/i/id), PNG/WAV/PDF, FFT and the distribution family, sparse matrices, and unary/reflected operators, alongside the earlier TOML, semver, UUID, PBKDF2, assertions, profiler, LSP rename/references and generators. Later the same day the database gap narrowed from "SQLite only" to three real drivers — Redis (RESP2), PostgreSQL (v3, all four auth methods) and MySQL/MariaDB (protocol 41) — each tested against a server that verifies the client's authentication maths. The transport gap closed next: SMTP (RFC 5321 plus an RFC 5322/MIME builder) and FTP (RFC 959, EPSV/PASV, byte-exact transfers through new streaming natives) are real clients, and SSH/SFTP drive the system OpenSSH client through a validated argv — no TLS stream yet, so the two network clients are cleartext-only by construction. The last library gap in this section closed with generated data rather than hand-written tables: IANA time zones (tzdata 2026e, 343 zones + 255 links, 1900–2100) and Unicode normalization and case folding (UCD 15.1), both regenerable from tools/ and both checked against CPython. The web-serving stack followed: multipart uploads that survive binary content, server-side sessions with real rotation and revocation, a middleware library, a keep-alive server with a graceful drain, and a FastCGI responder so nginx can front an app the way it fronts php-fpm. The last pass closed the tooling gaps: LSP semantic tokens and quick fixes, mocking/fixtures/line-coverage for tests, and a debugger with in-frame print, watches and a REPL. What still blocks real-world use, honestly: (1) no package registry — the ecosystem gap is the largest and only time plus registry work change it; (2) no suspension-based async executor (async/await are join-based; readiness itself is a kernel wakeup now, but via poll(2)/WSAPoll — O(n) per call, no epoll/kqueue); (3) databases beyond SQLite — Redis, PostgreSQL and MySQL/MariaDB clients now ship, but MongoDB, TLS, prepared statements and pooling do not; (4) SMTP, FTP and SSH clients now ship — SMTP and FTP are real protocol implementations but cleartext only (no TLS stream native, so no STARTTLS/AUTH TLS and credentials need an explicit opt-in), and SSH is a hardened wrapper around the system OpenSSH client rather than a native stack — and time zones and Unicode normalization now ship too (tzdata 2026e through 2100; UCD 15.1 NFC/NFD/NFKC/NFKD plus case folding), but collation is a three-strength model ordered by code points rather than UCA/DUCET, and there is no CLDR locale data; (5) generics are erased (parsed, not enforced) and the numeric stack is teaching-scale — no N-d arrays, no broadcasting, no BLAS — even though bigint has literal syntax (123n) and the maths is exact where it exists; (6) no JPEG or audio codec beyond PCM (PNG, WAV and PDF writing do work); (7) the Spid3r-source libraries are unavailable to spid3r build output today (the native backend still rejects import … as alias). The measured speed (≈2–4× CPython, PHP-class) is real but is the smallest of the differences that matter; the ecosystem remains the largest.
