Developer Guide · Package Management

Spid3r Package System (spkg)

Everything you need to create, structure, share, install, verify, and publish Spid3r packages using deterministic vendoring, content-addressed SHA-256 locking, and optional Ed25519 signature verification.

v1.1.1 Manifest: spider.toml Lockfile: spider.lock Vendored into: vendor/ CLI: spkg or spid3r pkg
Tool Entry Points
spkg & spid3r
Both invoke the exact same in-process package engine; spkg accepts commands directly or via spid3r init/add/install.
4 Package Sources
Path · Git · Dir · HTTP(S)
Install from local folders, Git URLs, local directory registries, or static HTTP/HTTPS package servers.
Integrity Model
SHA-256 + Ed25519
Deterministic hashing over relative paths + raw bytes, with optional signed sha256.txt.sig registries.
Execution Safety
Zero Install Hooks
No build scripts run during add or install, and POSIX tar extraction rejects symlinks and special files.

01Architecture Overview: How It Works

Spid3r uses a reproducible, vendored package workflow modeled around offline-friendly builds and verifiable lockfiles.

End-to-End Resolution & Vendoring Flow

When you run spkg install (or spkg add), Spid3r executes a deterministic pipeline:

  1. Reads spider.toml (single package or [workspace] root).
  2. Unifies semantic version constraints across transitive dependencies (for example, combining ^1.0.0 and =1.2.0 into 1.2.0).
  3. Fetches source files from a local path, Git checkout, local directory registry, or HTTP(S) registry cache under .spid3r/registry/.
  4. Copies only package sources and spider.toml into vendor/<pkg>/.
  5. Computes deterministic SHA-256 file digests and records exact versions, sources, file lists, and reverse dependents (used_by) in spider.lock.

How Imports Resolve Vendor Packages

The Spid3r compiler and runtime search vendor/ automatically alongside the project source root. When a dependency mathlib is vendored into vendor/mathlib/, you import its modules directly without extra include flags: 

import "mathlib/lib" as math;

fn main() {
    println("sum = " + math.add(20, 22).to_string());
}

Use spkg modules src/main.matrix --tree to inspect every imported module and verify which files came from stdlib, your project, or vendor/.

Default Public Registry: Out of the box, packages.registry points to https://spid3r-spkg.github.io. You can run spkg install <pkg>, spkg install <pkg>==<ver>, or spkg search right away, override the URL via SPID3R_REGISTRY or spid3r.ini, set SPID3R_REGISTRY=none in air-gapped environments, or install directly via --path / --git.

0260-Second Quickstart

Initialize a project, inspect the generated layout, and run or compile it immediately.

# 1. Quickest pip-style workflow in a fresh directory:
mkdir hello_demo && cd hello_demo
spkg install hello          # auto-inits spider.toml and installs latest
spkg search                 # browse online catalog.txt + vendor/

# 2. Or initialize an empty project explicitly:
spkg init my_app
cd my_app

# Generated files:
#   spider.toml       -> [package] metadata + [dependencies]
#   src/main.matrix   -> starter entry point

# 3. Install pinned version, verify, or uninstall:
spkg install hello==0.1.0
spkg tree
spkg verify
spkg uninstall hello
spkg dist                   # writes target/my_app.matrixc

You can invoke the same subcommands through the main spid3r binary (spid3r init, spid3r add, spid3r install, spid3r tree, spid3r verify, spid3r search, spid3r publish) or via spkg <command>.

03Developing & Writing a New Package

Author reusable Spid3r libraries or runnable applications with clean exports and predictable directory layout.

Recommended Library Layout

slugify/
├── spider.toml
├── src/
│   ├── lib.matrix       # public library API
│   └── helpers.matrix   # internal helpers
└── tests/
    └── basic_test.matrix

spkg init sets entry = "src/main.matrix" by default. For reusable libraries, update entry = "src/lib.matrix" in spider.toml so spkg pack, spkg dist, and tools know your library entry module.

Exporting Symbols with public

Any symbol imported from another module (functions, constants, classes, or enums) should be marked public: 

// slugify/src/lib.matrix
public const VERSION: string = "0.1.0";

public fn slugify(text: string) -> string {
    return text.trim().to_lower().replace(" ", "-");
}

Using Your Package From Another Project

# In a separate consumer project:
spkg init demo_app
cd demo_app

# Add the local library by relative or absolute path:
spkg add slugify --path ../slugify
// demo_app/src/main.matrix
import "slugify/lib" as slug;

fn main() {
    println(slug.slugify("Hello Spid3r Package"));
    println("lib version = " + slug.VERSION);
}
Import Path Mapping Rule: Source files inside a package's src/ folder are archived or vendored directly under vendor/<pkg>/. That means slugify/src/lib.matrix becomes vendor/slugify/lib.matrix and is imported as import "slugify/lib". Subdirectories such as src/net/client.matrix map to import "pkg/net/client".

04Manifest (spider.toml) & Lockfile (spider.lock)

Understand every supported key, dependency syntax form, and deterministic lockfile field.

Full spider.toml Example

[package]
name = "winplot"
version = "0.2.0"
entry = "src/lib.matrix"
description = "Data plotting & Windows GUI charting"
license = "MIT"
spid3r = ">=1.1.0"
categories = ["data-science", "gui"]
targets = ["windows-x86_64", "linux-x86_64", "any"]

[ffi]
# Optional declarative shared library metadata for extern fn bindings
libs = ["user32.dll", "gdi32.dll"]

[dependencies]
# Local path shorthand or inline table
slugify = "../slugify"
local_lib = { path = "../libs/local_lib" }

# Git dependency (defaults to branch/HEAD or pinned rev)
router = { git = "https://github.com/org/router.git", rev = "v1.2.0" }

# Registry dependency with SemVer / compound range
json_fmt = { version = ">=1.0.0, <2.0.0" }
internal_auth = { version = "=2.0.1", registry = "corp" }

Generated spider.lock Format

[[package]]
name = "json_fmt"
version = "1.4.2"
source = "registry+^1.4.0"
sha256 = "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
files = ["lib.matrix", "spider.toml"]
used_by = ["demo_app"]

spkg verify hashes every listed file inside vendor/<pkg>/ using exact relative paths plus raw bytes and checks for missing directories, changed hashes, extra/deleted files, or unlocked vendor directories.

Version Constraint Syntax

Constraint Behavior Example Matches
^1.2.3 / ^0.2.1 Standard SemVer caret: compatible within major if > 0, or within minor for 0.x (^0.2.1 matches 0.2.x, excludes 0.3.0) 1.2.3, 1.9.0 (not 2.0.0)
~1.2.3 Tilde range: same major and minor, at least patch 1.2.3, 1.2.9 (not 1.3.0)
>=1.0.0, <2.0.0 Compound AND ranges using >=, <=, >, < 1.0.0, 1.9.4 (not 2.0.0)
=1.2.3 or 1.2.3 Exact major.minor.patch pin (* matches any) 1.2.3 only

05Installing & Managing Dependencies (All 4 Sources)

Choose path, Git, local directory registry, or static HTTP/HTTPS registry sources per dependency.

Source Type Install Command spider.toml Form Notes
Local Path spkg add util --path ../util util = { path = "../util" } Great for monorepos and active local development; re-run spkg install to refresh vendor/.
Git URL spkg add router --git https://example.com/r.git --rev v1.0.0 router = { git = "...", rev = "v1.0.0" } Supports https:// and ssh:// by default. Plain http:// and local file Git repos are blocked unless explicitly opted in.
Local Registry spkg add json_fmt --version "^1.2.0" json_fmt = { version = "^1.2.0" } Resolves against $SPID3R_REGISTRY/<name>/<ver>/ (or named sub-registry subdirectory).
HTTP(S) Registry spkg install hello or spkg install hello==0.1.0 hello = { version = "^0.1.0" } Defaults to https://spid3r-spkg.github.io; downloads index.txt, sha256.txt, optional sha256.txt.sig, and package.tar into .spid3r/registry/.

Updating, Removing, and Auditing

# Install dependencies pinned to spider.lock when compatible
spkg install

# Ignore previous lockfile pins and resolve newest matching versions
spkg install --update

# Show full dependency graph
spkg tree

# Verify vendor/ integrity against spider.lock (CI recommended)
spkg verify

# Remove a dependency from spider.toml, vendor/, and spider.lock
spkg remove util

Searching Local & Vendored Packages

# Search configured $SPID3R_REGISTRY plus current project vendor/
spkg search json

# Search only the current project vendor/ directory
spkg search json --local

When spkg add or spkg remove edits spider.toml, it modifies lines textually so existing comments and section ordering remain intact.

06Multi-Package Workspaces

Manage multiple cooperating packages in one repository with shared dependency resolution and locking.

Workspace Root Layout & Configuration

A workspace root spider.toml declares [workspace] with members. A workspace root may omit [package] when it only coordinates member crates: 

my_workspace/
├── spider.toml
├── spider.lock          # single shared lockfile at workspace root
├── vendor/              # shared vendored dependencies
├── core_lib/
│   ├── spider.toml
│   └── src/lib.matrix
└── cli_app/
    ├── spider.toml      # can depend on core_lib = { path = "../core_lib" }
    └── src/main.matrix
# my_workspace/spider.toml
[workspace]
members = ["core_lib", "cli_app"]

Running spkg install or spkg tree inside the workspace resolves dependencies across all listed members, unifies overlapping SemVer constraints, and checks shared integrity with spkg verify.

07Publishing, Tar Packaging & Static Registries

Publish immutable versioned releases to a local directory or host a zero-backend static HTTP/HTTPS registry.

Publish to a Registry Directory

# Export current package into /srv/spid3r-registry/<name>/<version>/
spkg publish --to-dir /srv/spid3r-registry

# Install from that local registry in another project
SPID3R_REGISTRY=/srv/spid3r-registry spkg add slugify --version "^0.1.0"

Publishes are immutable: if <dir>/<name>/<version>/ already exists, spkg publish refuses to overwrite it so previously locked builds cannot silently change.

Static HTTP(S) Registry Layout

<base>/
├── registry.toml              # host descriptor, moved_to migration, mirrors
├── registry.pub               # 64-hex Ed25519 public key
├── catalog.txt                # searchable index + categories + targets
└── <pkg-name>/
    ├── index.txt              # available versions (lazy fetch reads index first)
    └── <version>/
        ├── spider.toml
        ├── sha256.txt         # streaming SHA-256 over src/
        ├── sha256.txt.sig     # verified before tarball download/extract
        ├── manifest.sha256    # canonical manifest + src/ digest
        ├── manifest.sha256.sig
        └── package.tar        # bounded archive (<name>-<ver>.tar fallback)

To migrate domains later, copy the static files to your new host, set moved_to = "https://new-host" in the old registry.toml, or set SPID3R_DEFAULT_REGISTRY when building future toolchains.

Self-Contained Tar Packing

# Bundle spider.toml and src/ into a clean POSIX ustar tar archive
spkg pack -o dist/my_pkg-0.1.0.tar

# Extract into a new directory
spkg unpack dist/my_pkg-0.1.0.tar ./extracted_pkg

TLS Feature Note for HTTPS Registries

Prebuilt binaries compiled with the tls Cargo feature (cargo build --features "native tls") fetch both http:// and https:// registries directly. Binaries compiled with --no-default-features support local directory registries, --path, --git, and http:// registries, and report an explicit error asking for a tls-enabled build if given an https:// registry URL.

08Security, Ed25519 Signing & spid3r.ini

Verify signed registries, enforce transport policies, and configure machine-wide defaults in spid3r.ini.

Ed25519 Registry Signing & Verification

# Publisher: provide a 64-hex-char Ed25519 secret seed
# (or let publish read/generate registry.key in the target registry dir)
SPID3R_SIGN_KEY=<64-hex-seed> spkg publish --to-dir /srv/registry
# Writes registry.pub + <ver>/sha256.txt.sig (128-hex signature)

# Consumer: require valid Ed25519 signatures matching trusted 64-hex key
SPID3R_TRUST_PK=<64-hex-pubkey> SPID3R_REGISTRY=https://pkg.example.com spkg install

When SPID3R_TRUST_PK or packages.trust_pk is set, every registry package must provide a valid sha256.txt.sig signed by that exact public key; missing or invalid signatures fail installation immediately.

Security Hardening Guarantees

  • No install-time code execution: spkg add and spkg install never run arbitrary pre/post-install shell scripts.
  • Pre-extract Ed25519 & manifest integrity: When trust_pk is set, signatures and manifest.sha256 are checked before untrusted tarballs are extracted, and key rotation accepts comma-separated public keys.
  • Bounded archive & path sanitization: Tar extraction caps entries (10,000) and size (128 MiB), blocks traversal, Windows reserved names, case-insensitive collisions, and refuses symlinks in packages, vendoring, and Git checkouts.
  • Atomic vendoring & Git hardening: Dependencies stage and hash-verify before swapping into vendor/, and Git runs with symlinks, hooks, and submodules disabled.

spid3r.ini [packages] Keys & Environment Overrides

spid3r.ini Key Environment Variable Default Purpose
packages.registry SPID3R_REGISTRY https://spid3r-spkg.github.io Default registry URL/directory or comma-separated mirror list (set none to disable).
packages.trust_pk SPID3R_TRUST_PK Unset One or more comma-separated 64-hex Ed25519 public keys for zero-downtime key rotation.
packages.allow_insecure_git SPID3R_ALLOW_INSECURE_GIT false Allow unencrypted http:// Git dependency URLs (recommended false in production).
packages.allow_local_git SPID3R_ALLOW_LOCAL_GIT_DEPS false Allow local filesystem paths as git = "..." URLs (prefer path = "..." instead).
N/A (auth env) SPID3R_REGISTRY_TOKEN Unset Optional Bearer token sent only over https:// to the initial registry origin (stripped on cross-origin redirects).
N/A (publisher env) SPID3R_SIGN_KEY / SPID3R_PACKAGES_SIGN_KEY Unset 64-hex Ed25519 signing seed used by spkg publish --to-dir.

09Complete CLI Reference

All verified commands exposed by spkg (and mirrored through spid3r).

Command Flags / Arguments Description
spkg init [dir] Optional target directory (default .) Create a starter spider.toml and src/main.matrix.
spkg add <name>[==V|@V] --path P | --git URL [--rev R] | --version V Add a dependency entry to spider.toml (latest registry version if source omitted), vendor files into vendor/, and update spider.lock.
spkg remove <name>... / uninstall One or more package names Remove dependencies from spider.toml, delete their vendor/<name> folders, and update spider.lock.
spkg install [<pkg>...] [--update | -u] [--frozen] [--offline] [--dev] [--extra E] Install named packages like pip or vendor project deps, dev/optional groups, and per-target native wheels.
spkg list / show <pkg> [--json] List locked dependencies and verification status, or show full metadata, hashes, and [ffi] surface for one package.
spkg outdated [--offline] Check registry dependencies against the latest non-yanked versions.
spkg audit [--json] [--offline] Verify hashes, signatures, Git pinning, [ffi] binaries, yanked versions, and security advisories.
spkg freeze [--sbom] Export pinned name==version lines or a CycloneDX JSON SBOM.
spkg tree None Print the resolved dependency tree for the current package or workspace.
spkg verify None Re-hash every file under vendor/ and _native/ against spider.lock.
spkg search [query] [--category CAT] [--local] Search remote catalog.txt (or local registry directory) and vendor/ entries; filter by ecosystem category or omit query to list all.
spkg publish --to-dir <dir> [--target T] Publish an immutable signed release (or per-target wheel) with sha256*.txt.sig and signed index.txt.sig.
spkg pack [-o out.tar] [--target T] Create a clean POSIX ustar archive containing spider.toml, src/, and optional native/<target>/.
spkg unpack <archive> [dir] Archive path, optional output dir Safely extract a packed project archive after validating entry types and relative paths.
spkg cache [dir | list | prune] Inspect or clear the shared global package cache.
spkg tool install|list|uninstall <pkg> Install verified CLI tools declaring [bin] into isolated environments with launcher shims in bin/.
spkg dist [-o out] [--no-opt] Compile the package entry module into target/<pkg>.matrixc bytecode.
spkg modules <file> [--tree] List all imported modules referenced by <file> along with their resolved origins.
spkg version / help None Print the spkg version string or command usage help.

10Troubleshooting & FAQ

Quick fixes for common issues when creating, installing, or verifying packages.

Why does import "my_pkg/lib" say module not found?

Confirm two things: first, run spkg install so files exist inside vendor/my_pkg/; second, remember that files inside my_pkg/src/ map directly under vendor/my_pkg/ (so src/lib.matrix is imported as "my_pkg/lib", without src/ in the import string). Run spkg modules src/main.matrix --tree to inspect search resolution.

Why did spkg verify fail after editing a file in vendor/?

vendor/ is managed by spkg and hash-checked against spider.lock. Edit the original package source (for example via your --path folder), then run spkg install to re-vendor and refresh spider.lock cleanly.

Why is my https:// registry rejected on a minimal build?

If your binary was built without TLS support (for instance --no-default-features), HTTPS downloads cannot negotiate TLS. Build with cargo build --features "native tls" (or --features tls), or host an internal registry over a mounted directory or LAN HTTP mirror.

Should I commit spider.lock and vendor/ to Git?

Commit spider.toml and spider.lock in every project and CI pipeline. Commit vendor/ as well when you want 100% air-gapped offline builds without touching Git remotes or registries during CI; otherwise CI can run spkg install && spkg verify.
