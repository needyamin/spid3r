01Scope & Covered Software

This Privacy Policy applies to all official Spid3r programming language distributions, developer tools, and static web documentation published by ANSNEW TECH.:

Desktop & CLI Toolchain

  • Core CLI & runtime executables: spid3r, sp, yamc, yamcvm, spvm, and spkg.
  • Self-hosted AOT compiler: spid3r-self powered by YamLLVM (LLVM 23) and the SHA-256-pinned spid3r_lang static library.
  • Desktop Control Panel: spid3r-control (optional GUI binary) and spid3r control for editing local spid3r.ini settings.
  • Editor extension: Bundled VS Code formatter package (spid3r-formatter.vsix).

Installers, Store Packages & Web Runtime

  • Microsoft Store MSIX package: Package Identity ANSNEWTECH.Spid3r (Store ID 9NPH5XX0F6KF, Spid3r-<ver>-x64.msix).
  • Standalone installers & archives: Windows NSIS installer (Spid3r-Setup-<ver>.exe) and Linux/macOS release tarballs.
  • WebAssembly browser tools: Offline-capable documentation (doc.html), benchmark report (benchmark.html), and browser playground (playground.html) backed by web/spid3r.wasm.

02Data Collection & Telemetry

By design, the Spid3r software contains no telemetry subsystem, no advertising SDKs, and no background network services. When you install or run Spid3r, ANSNEW TECH. does not collect, access, log, or sell any of the following:

  • No personal identifiers: Names, email addresses, Microsoft Store account identities, IP addresses, or payment details are never accessed or transmitted by Spid3r binaries.
  • No device or usage telemetry: Spid3r never reports hardware fingerprints, OS versions, CPU metrics, command frequency, or feature usage statistics.
  • No source code or build output: Your .matrix / .mt source files, .matrixc bytecode, compiled binaries, and spid3r.ini policies never leave your machine through Spid3r tooling.
  • No silent crash reporting or background daemons: Errors and stack traces are printed strictly to your local terminal or stderr. Spid3r does not install background telemetry or remote update services.

04Local Files, Configuration & Data Deletion

All data created during normal use stays exclusively on your device under directories you control:

What Is Stored Locally

  • Configuration: Optional spid3r.ini files (local project directory, user config directory, or system path; 45 schema keys across 12 sections).
  • Project & package files: Your .matrix / .mt sources, compiled executables, .matrixc artifacts, spider.toml, spider.lock, and vendored packages.
  • Web documentation preferences: Browser localStorage stores UI theme selection (spid3r-dev-theme: light or dark) and local editor scratch state in the playground. No third-party tracking cookies are set.

How to Delete Your Data

  • Microsoft Store package: Right-click Spid3r in the Windows Start Menu → Uninstall, or remove via Windows Settings → Apps → Installed apps.
  • Windows NSIS / tarballs: Run the Spid3r uninstaller from Windows Apps or remove the extracted toolchain directory (for example ~/.spid3r).
  • Configuration & browser state: Delete any local spid3r.ini files and project folders you created, and clear site storage / localStorage in your browser settings if desired.

05Security & Execution Trust Model

Privacy and execution integrity go hand in hand. Spid3r separates trusted compilation from opt-in script capability controls:

  • Script authority model: Just like Python or shell scripts, a .matrix program executes with the permissions of the user account that launches it unless restricted with --sandbox, --budget N, spid3r.ini (security.deny_*, security.basedir, modules.disable), or Rust embed Engine::deny_all().
  • Tamper verification: v3 .matrixc bytecode containers and spid3r_lang runtime staticlibs verify SHA-256 digests before execution and fail closed with exit code 4 on mismatch.
  • Fail-closed configuration pinning: Setting SPID3R_INI requires the pinned config file to load cleanly (exiting with code 1 rather than falling back to defaults if missing or malformed).
  • Vulnerability reporting: Security issues can be reported privately through GitHub Security Advisories or our full Security Policy.

  • Microsoft Store (ANSNEWTECH.Spid3r · Store ID 9NPH5XX0F6KF): Installation, updates, crash diagnostics you opt into via Windows Privacy Settings, and regional store distribution are governed by the Microsoft Privacy Statement. ANSNEW TECH. receives only anonymized, aggregate Store Partner Center statistics and never receives personal user data from inside the Spid3r app.
  • GitHub Hosting (needyamin/spid3r): Accessing source code, release tarballs, issue trackers, or security advisories on GitHub is governed by the GitHub Privacy Statement.
  • Third-Party Package Registries: When you invoke spkg / spid3r install against a custom HTTP/Git registry, network requests are governed by the operator of that registry URL.
