1. PROJECT SNAPSHOT
--------------------------------------------------------------------------------
Project   : Spid3r v1.0.0 - a programming-language toolchain written in Rust.
            Language source files use the extension `.matrix`.
Engines   : (1) tree interpreter  (`spid3r run f.matrix`)
            (2) bytecode VM       (`spid3r run --engine vm f.matrix`)
            (3) LLVM native (AOT) (`spid3r build f.matrix -o out.exe`; run out.exe)
            (4) wasm C-ABI build exists too (web/spid3r.wasm), not touched here.
Layout    : src/           compiler, interpreter (src/interpreter/mod.rs),
            VM (src/vm/), LLVM backend (src/native/), lexer (src/lexer/mod.rs),
            parser (src/parser/mod.rs), semantic (src/semantic/mod.rs),
            stdlib (src/stdlib/*.rs incl. regex.rs), value/GC (src/value/gc.rs),
            scheduler (src/sched/mod.rs), CLI (src/cli.rs)
            stdlib/        first-party Spid3r modules (bigint, math_util, ...)
            tests/         ~80 Rust integration test files
            docs/          GRAMMAR.md, STANDARD_LIBRARY.md, GC.md,
                           ENGINE_CONTRACT.md, KEYWORDS.md, BUILDING.md, ...
            docs/html/     bug_report.html (see 6.1 - DELETED from disk!),
                           report.html (field-test report), playground.html
            examples/      .matrix example programs

            audit/         audit probes (probes_r3/ etc.)
            tools/         count_tests.sh etc.

3. CRITICAL ENVIRONMENT WARNINGS FOR AGENTS
--------------------------------------------------------------------------------
3.1 WRITE-GUARD FALSE POSITIVE ("key name token"):
    The workspace write-guard flags any write whose payload/resulting file
    contains text shaped like `crate::lexer::token::{...}` (it misreads the
    Rust import as `token = <secret>`). Consequences:
      - lexer/mod.rs was REFORMATTED to avoid it: the import is now
        `use crate::lexer::token as tok_mod;` + `use tok_mod::{Keyword, Token, TokenKind};`
        and all references use `tok_mod::InterpPiece`. DO NOT reintroduce
        `crate::lexer::token::` text into lexer/mod.rs.
      - parser/mod.rs STILL CONTAINS 3 trip-lines (line 5 import,
        line 1922 `&[crate::lexer::token::InterpPiece]`, line 1925 test import).
        Any edit to parser/mod.rs will be blocked until those are aliased the
        same way (the user has already approved this pattern once - ask/reformat
        identically: `use crate::lexer::token as tok_mod;`).
    If a read/display shows `token=[redacted]`, that is the DISPLAY filter - to
    see true bytes, read the line via exec with a char-code join:
      ($l = (Get-Content 'src\lexer\mod.rs')[3]; ($l.ToCharArray() | % { [int]$_ }) -join ',')
    (That is how the exact import line was recovered; it was NOT a credential.)
3.2 Spid3r language: there is NO `&&`/`||` - the operators are `and`/`or`.
    String interpolation: `{name}` / `{path.to.field}` / `{call()}` are holes;
    bare-integer holes `{2}` were REMOVED in the F-1 fix (2026-10-25) so regex
    quantifiers are writable; `{{` is never an escape. An identifier-shaped
    brace in a string (`"a{x}"`) IS a hole - build such strings by
    concatenation when you need literal braces (see f1_verify.matrix).
3.3 `spid3r compile` output is bytecode, not an executable; use `spid3r build`
    for native. `compile -o` writes an extensionless file on Windows (open F-2).
3.4 Never print `gc_live_cells()` in cross-engine programs - the value is
    engine-internal (see finding F-3). Deterministic programs: use
    insertion-ordered maps (guaranteed) and fixed seeds; print nothing
    order-dependent from spawned tasks (aggregate in main, keyed by id).
3.5 PowerShell 5.1: `&&` is unavailable in the shell too; use `;` or separate
    calls. Cargo build lock: run cargo commands sequentially, not in parallel.
