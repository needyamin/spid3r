[1] WHAT THIS PROJECT IS
--------------------------------------------------------------------------------
Spid3r ("GaliLang" is the folder name; the language is Spid3r): a dynamically
typed programming language implemented in pure Rust, zero third-party
dependencies (crate `spid3r`, edition 2021, license MIT).

One front end, two execution engines that MUST stay semantically identical:
    lexer -> parser -> semantic checker --+--> tree-walk interpreter ("tree",
                                          |    the reference engine)
                                          +--> bytecode compiler -> stack VM
                                               ("vm", with optimizer)

Also included: module system (import/privacy), task concurrency (spawn/await,
channels, mutexes), 20+ builtin collections, cycle-collecting GC, a project /
dependency layer (spider.toml, vendor/, local registry, tar packing), formatter,
REPL, line debugger, a Language Server Protocol server (`spid3r lsp`, see
docs/LSP.md), optional LLVM AOT backend (feature "native"), optional
webview GUI (feature "gui"), and an NSIS Windows installer (packaging/).

State: 669 Rust tests green (653 core incl. 2 doc-tests + 10 GUI + 6 AOT;
embed-API round 2026-10-20, stdlib expansion round 2026-10-20, bytes & CSV &
regex & datetime round 2026-10-20, master audit & non-regression sweep
completed 2026-10-20, Stage-2 concurrency round 2026-10-20, scheduler-limits
round 2026-10-21, LSP round 2026-10-21),
25/25 examples pass the three-engine differential. Language version 1.0,
crate version 1.0.0.

[5] ARCHITECTURE INVARIANTS — DO NOT BREAK
--------------------------------------------------------------------------------
  1. The tree interpreter and the VM must behave IDENTICALLY. Any semantic
     change must be made in both, and covered by a differential test
     (tests/audit_regressions.rs pattern or tests/difftest.rs).
  2. All value semantics live in value::collections; engines delegate. Do not
     add engine-specific semantics.
  3. User code must never panic the Rust host: return Diagnostic / VmError /
     Err(String). `.lock().unwrap()` is used pervasively — avoid holding a
     collection's Mutex while recursing into values that may re-lock it
     (self-referential containers deadlock; see json_write fix pattern:
     clone-out under lock, recurse without).
  4. Zero third-party dependencies for the default feature set.
  5. `cargo test` must stay green; never delete/disable failing tests to pass —
     fix the cause or (documented contract changes only) update the test with a
     comment citing the doc.
  6. Closures: cells are per-activation (CallFrame.own_cells); for-in rebinds
     the loop var per iteration (Uncapture opcode, byte 53); while/C-style for
     share one binding; scope exits and break/continue emit Uncapture for
     captured locals; current-frame locals always use GetLocal/SetLocal
     (routed through frame.captured); VmFuncProto.upvalues encodes direct parent
     local captures with bit 7 = 0 (parent.own_cells[u & 0x7f]) and parent
     enclosing upvalue captures with bit 7 = 1 (parent.func.upvalues[u & 0x7f]).
  7. Modules are keyed by canonicalized path everywhere (interpreter, VM cache,
     AOT flattener, and the Import opcodes carry the resolved path string).
  8. Host-shell note: the automation shell has a minimal environment; scripts
     must use absolute paths, not $env:USERPROFILE etc.

[12] KNOWN QUIRKS / OPEN ISSUES (do not "fix" blindly; see docs/AUDIT_REPORT.md §8)
--------------------------------------------------------------------------------
  - Lexer: float literals support scientific notation (1.5e3, 1e-5, 2E+4) and
    an out-of-f64-range literal is a clean lexer error;
    -9223372036854775808 literal is unrepresentable before unary negation.
  - GC traces all 20+ container and instance types automatically via value::new_ref.
  - Concurrency contract (Stage 2 + limits round, 2026-10-20/21):
    * gc_collect() is refused only while another thread is *running* Spid3r
      code (the mark-sweep precondition). Tasks parked in recv/join/mutex/sleep
      do not block it; the automatic collector uses the same gate.
    * the pool grows on demand so blocked tasks (recv/join/mutex/sleep) never
      starve queued work, up to SPID3R_MAX_WORKERS (default 256). At that
      ceiling a stall is reported on stderr by the watchdog instead of hanging
      silently.
    * the ready queue is bounded (SPID3R_QUEUE_CAP, default 65536); spawn grows
      the pool first and then parks the producer, so a spawn storm cannot grow
      memory without limit and no task is dropped.
    * program exit drains tasks (SPID3R_TASK_DRAIN_MS, default 2000) and the
      CLI/AOT then call Scheduler::shutdown(), which stops and joins the worker
      threads; the singleton restarts if something spawns afterwards (REPL/embed).
    * a thrown value crosses spawn/await/task.join()/callback seams as the
      value itself, so catch rebinds maps/objects (both engines + AOT).
    * detached collection mutators (list/set/bag remove+add) commit with a
      verified snapshot and retry on conflict (bounded, 32) — concurrent adds
      cannot duplicate, concurrent removes cannot hit a shifted slot.
  - Syntax gaps (2026-10-21):
    * `else if (c) { … }` is accepted as a synonym for `elif`, and the two may be
      mixed in one chain. It was a parse error, which is a gratuitous difference
      from every C-family language.
    * the `[]` operator takes a NEGATIVE index on list/tuple/string (`-1` is the
      last element), for both read and write. `collections::seq::resolve_index`
      maps it and reports the index the user wrote when out of range. Method
      arguments (remove/insert/slice) stay non-negative.
    * `want_index` no longer says "found int" for a negative int: it names the
      value, and non-integer indices say what type they got.
  - Lints (Stage 7, 2026-10-21):
    * Four warnings: unused-variable, unused-parameter, unused-import,
      unreachable-code. `Diagnostic` gained `severity` + `lint` (both 1 byte,
      fitting the padding after `phase`, so the struct did not grow).
    * `check_file_with_warnings` returns them; `check_file` stays validity-only
      so the VM/native/module callers are untouched. Warnings are sorted by
      position (they surface inside-out as scopes close).
    * `check` prints them, `--deny-warnings` makes them fail (exit 1), and
      `--allow LINT` silences one. `--json` tags each with severity + lint.
    * POLICY: scope 0 (the file's top level) only reports unused *imports* —
      a private global may be used from another module and a public one is an
      export. `_`-prefixed names are always exempt (the callback convention).
    * FALSE POSITIVE found and fixed: a call's callee was looked up without
      being visited, so `let f = ...; f()` reported `f` as unused. `mark_used`
      now runs in the Call arm.
    * examples/web_service.matrix: three route callbacks that ignore `req` are
      now `_req`, demonstrating the convention; the one that reads
      `req.params` keeps its name.
  - Diagnostics (Stage 6, 2026-10-21):
    * `Diagnostic::render()` prints message, `-->` location, the source line
      with a caret under the span (tabs expanded, CHARACTER columns), then
      `= note:` / `= help:` lines, then the trace. The source is read from the
      span's file; when that fails the plain form is used, never a guess.
    * `= help:` is attached where it changes what the user does — type
      mismatches (`Checker::mismatch`) suggest `any` or an explicit conversion.
    * `spid3r check --json` prints one JSON object (phase/message/file/line/
      col/len/help/notes/trace) for editors and CI.
    * Diagnostic help/notes live in ONE boxed `Option<Box<DiagnosticExtras>>`,
      not two inline fields: `Diagnostic` sits in every `Result`, and the
      bytecode serializer/deserializer is recursive, so its size is multiplied
      by the nesting depth. Two inline fields (48 bytes) overflowed a 2 MB
      thread stack at 200 levels of nesting.
  - Ergonomics (Stage 2c, 2026-10-21):
    * `let (a, b) = expr;` lowers to `let __d = expr; let a = __d[0]; …` — one
      evaluation, ordinary bindings. New `Stmt::LetTuple`, expanded by lower.
    * `for (k, v) in m` lowers to `let __src = m; for k in __src { let v =
      __src[k]; … }`. `Stmt::ForIn` gained `var2: Option<String>`; the engines
      still only see one variable. GOTCHA: the lowering fast-path scan must test
      `var2.is_some()`, or a program whose only construct is `for (k, v)` is
      passed through unchanged and the value binding never exists (runtime
      "unknown name").
    * `spawn` accepts any callable (`spawn work`, `spawn closure_var`); the
      parser and the checker dropped their `matches!(Expr::Fn)` restriction —
      the runtime already handled any function value and reports a clean error
      otherwise.
  - Error model (Stage 4, 2026-10-21):
    * `some`/`none` normalise to `option`, `ok`/`err` to `result`, so an
      annotation like `let x: option<int> = some(5)` finally type-checks (it
      used to fail with "expected option, got some" — the annotation was
      unusable).
    * collection annotations now compare ELEMENT types (`list<int>` vs
      `list<string>` is a mismatch; an unknown element type such as `[]` or
      `none()` stays compatible). `result` is exempt because one type argument
      cannot describe both sides.
    * `Ty::name` prints the element (`list<int>`), so the mismatch message says
      something.
    * `expr?` lowers to `let v = e; if (is_failure(v)) { return v; } v.unwrap()`.
      Works on option and result; `is_failure` is a normal builtin.
    * option: map/and_then/ok_or/unwrap_or_else/flatten; result:
      map/map_err/and_then/unwrap_or_else/flatten. They take callbacks, so the
      VM needed a callback-host arm for Option/Result (it only had one for
      List) and `and_then`/`map_err`/`unwrap_or_else` had to join
      `is_callback_method`.
  - Sum types (Stage 3, 2026-10-21):
    * `enum Name { A, B(x) }` lowers to one PUBLIC constructor function per
      variant: `A()` / `B(1)` return a map with a `__tag` key plus one key per
      field. Construction is therefore an ordinary call, so it works across
      `import` with no name-resolution step, and no backend changed.
    * `match (v) { P => body }` lowers to a linear chain:
      `let __s = v; let __t = null; let __d = false;` then one
      `if (not __d and <test>) { <binds>; if (<guard>) { <body>; __d = true } }`
      per arm, then `if (not __d) { throw "no match arm matched …" }`.
      The `__d` flag keeps the chain linear: a failed guard falls through
      without duplicating the remaining arms.
    * patterns: variant `Circle(r)`, literal, binding `x`, wildcard `_`, and
      nesting (`Dot(At(x, y))`). Bindings are scoped to the arm.
    * exhaustiveness: a match whose variant patterns all belong to one enum and
      that has no `_`/binding arm must cover every variant (semantic error
      naming the missing ones). Otherwise an unmatched value throws at runtime.
    * `public enum` exports its VARIANTS (modules::public_names_of_in), because
      the variant names are the constructor functions.
  - Value forms (Stage 2b, 2026-10-21):
    * `if` works in value position; a branch's last expression may omit its `;`
      and a missing `else` yields null. `return` inside a branch returns from
      the enclosing function (the reason an IIFE lowering was rejected).
    * `a ?? b` evaluates `b` only when `a` is null; `obj?.field` evaluates the
      receiver once and yields null for a null receiver.
    * all three are lowered away before any backend runs, so no engine changed.
      A program without them is passed through by reference.
    * MAX_PARSE_DEPTH is now 64 (was 96): each nesting level costs ~13 parser
      frames, and 96 overflowed a 2 MB thread stack once one precedence level
      was added.
    * AOT FIX found by the matrix: `map.field` aborted with "cannot read field
      'k' of map" in the native backend while tree and VM read the key. The
      runtime helper now has the map arm.
  - Syntax batch (Stage 2, 2026-10-21):
    * string interpolation: `{name}` / `{obj.field}` (no whitespace inside the
      braces) desugars in the PARSER to `+ string(...)` calls, so the checker
      reports unknown names for free and no engine changed. A hole requires an
      identifier immediately after `{`, so `"{{ user }}"`, `"{ x }"`, `"{}"` and
      `"{0}"` stay literal — the stdlib template engine depends on that.
    * bitwise `& | ^ << >>` with C precedence, desugared to the natives
      `bit_and`/`bit_or`/`bit_xor`/`shl`/`shr` (one implementation, all three
      engines). `^` is xor, NOT exponentiation (doc.html said otherwise until
      now). A shift amount outside 0..=63 is a clean error.
  - Pipeline seam (Stage 1, 2026-10-21):
    * every backend executes the LOWERED AST (`crate::lower`): the interpreter
      lowers in run_program_inner, modules::load lowers an imported module, the
      VM lowers in compile_program_unoptimized, the AOT backend in
      build_module. The pass is the identity today; the seam exists so a
      syntax feature is written once.
    * a VM failure while EXECUTING reports `error[runtime]`, not `error[vm]`
      (Phase::Vm is reserved for malformed bytecode / compile failures). The
      same program used to report a different phase per engine; the matrix
      caught it because `spid3r test` compares stdout only.
    * `tests/engine_matrix.rs` asserts EXPECTED output, not just engine
      agreement, so two engines cannot agree on the wrong answer.
  - Correctness round (Stage 0, 2026-10-21):
    * every flat container AND instance type tears down through one iterative
      worklist (collections::drop_iteratively); a 1M-deep chain is fine, and a
      *mixed* chain no longer overflows (the three per-type guards each knew
      only their own type plus `list`).
    * deep_clone preserves cycles: a back-reference resolves to the clone, not
      the original (copy.deepcopy semantics). A value reachable by two paths is
      shared in the copy, not duplicated.
    * the regex engine scans once (start-anywhere thread), O(n*states); a
      negated class now matches a newline (only `.` excludes it).
    * HTTP framing has a deadline: SPID3R_NET_TIMEOUT_MS (30000, 0 disables),
      applied only if the program did not call tcp_set_timeout.
    * .npy shape arithmetic is checked (a crafted header reports "too large");
      save_npy rejects a shape that disagrees with its payload.
    * diagnostic columns and span lengths count CHARACTERS, not bytes.
    * `spid3r test` takes --filter/--list and rejects unknown arguments.
    * CLOSURES STILL LEAK (A-13, open): env -> closure -> env is not collected,
      measured at one cell per closure. See docs/GC.md for what a fix requires.
  - Artifact and dependency hardening (Stage 3, 2026-10-21):
    * git dependencies accept only https://, ssh://, and scp-like URLs. Plain
      http/git need SPID3R_ALLOW_INSECURE_GIT=1; local paths and file:// need
      SPID3R_ALLOW_LOCAL_GIT_DEPS=1; `ext::` (git's run-a-command transport) is
      rejected unconditionally.
    * spider.lock pins git commits: a re-install checks out the recorded commit
      and verifies HEAD; `spid3r install --update` is the only way to move.
    * vendor hashes cover every file under src/ as raw bytes (path NUL contents
      NUL). sha256.txt files generated before 2026-10-21 must be regenerated.
    * a .matrixc must end in return/throw/jump, have inst_offsets and inst_spans
      agree, contain no trailing bytes, and nest < 128 levels; the VM's
      instruction fetch is bounds-checked.
    * a release build never downloads: the WebView2 bootstrapper is opt-in
      (SPID3R_FETCH_WEBVIEW2=1) and SHA-256-verified before use.
  - tar supports POSIX ustar prefix (<= 255 bytes), GNU @LongLink (> 255 bytes),
    and header checksum verification.
  - int overflow wraps silently; int/int truncates toward zero; err(...) is
    truthy; comparison chains left-associative; assignments legal in conditions.
  - native backend rejects class-declared-inside-function (clean diagnostic).
  - VM encoding limits (clean diagnostics; the tree engine has no such limit):
    a list literal may hold at most 255 elements; a function may capture at
    most 128 variables (7-bit upvalue descriptor encoding).
  - Self-referential container ops USED TO HANG both engines (mutex re-entry):
    for-in over a self-containing list, set.union(s) with itself, map.values()
    of a self-valued map, linked_list.to_list() of a self-referencing list —
    FIXED 2026-10-19 (snapshot-under-lock in the shared value layer; tests/
    fix_f3_hangs.rs). Deep nested list/map/set chains also tear down
    iteratively now (deep builds verified to 4M levels; tests/fix_f4_gc.rs).
    See docs/AUDIT_REPORT.md section 10 and plan.html.
  - The remaining re-entry families were fixed 2026-10-20 (audit A-7, Stage 2;
    tests/stage2_concurrency.rs): list.slice / list.contains / index_of /
    remove, stack|queue|deque|ring to_list+contains, set add/remove/to_list,
    bag add/remove/count_of/contains, binary_tree traversals, and graph
    nodes()/clone()/bfs/dfs/neighbors/path_exists/find_path/add_edge.
    RULE: never call values_equal/deep_clone while holding the receiver's
    Mutex — snapshot under the lock, then recurse without it.
