Spid3r

A small, dynamically typed programming language with optional static types. Programs run on a tree-walking reference interpreter or a bytecode compiler + stack VM, and both engines are differentially tested to agree.

Overview

ENGINE ARCHITECTURE

Dual Execution Engines: Tree-Walk Reference Interpreter vs Stack VM

Both engines share an identical frontend (Lexer → Parser → AST → Semantic Checker) and execute with differential equivalence guarantees.

Spid3r uses plain lowercase keywords (fn, let, class, spawn, import) on top of real semantics: dynamic types, closures with upvalues, single-inheritance classes with interfaces, structured error handling, modules with visibility, task-based concurrency, a standard library, and a suite of 20+ built-in data structures. The language core has no third-party dependencies; the webview GUI and the LLVM native backend are included in the standard installer.

Two engines, one front endThe lexer, parser, and semantic checker are shared. Run on the tree-walk interpreter or compile to bytecode for the VM.
Self-contained bytecodecompile embeds every imported module, so exec runs a .matrixc with no source on disk.
Differentially testedEvery example runs three ways (tree, VM, compile + exec) and must print identical output.
Gradual typingOptional annotations on variables, parameters, returns, and fields, checked before the program runs.
Task concurrencyspawn / async / await, channels, mutexes, and shared cells on a threaded scheduler.
Batteries includedFormatter, REPL, line debugger, benchmark runner, package manager, a webview GUI backend, and an LLVM AOT compiler for native executables.

Installation

Spid3r ships prebuilt — there is nothing to compile and no dependencies to install first. On Windows, run Spid3r-Setup-1.0.0.exe; on Linux and macOS, run the one-line installer. Both give you the spid3r command-line tool: the tree-walk interpreter, the bytecode VM, the package manager, the formatter, the REPL, the debugger, and the language server.

Windows installer

Run Spid3r-Setup-1.0.0.exe. It installs the spid3r toolchain into %LOCALAPPDATA%\Programs\Spid3r and adds that directory to your user PATH (terminals started after the install pick it up; already-open ones do not). The installer always ships the spid3r.exe binary, the standard library (stdlib/), and — for the native backend — LLVM-C.dll, LLVM-C.lib, and the spid3r_lang.lib runtime library that spid3r build links into programs. Optional components:

  • Examples, documentation & reference — README.md, docs/, examples/, and the web/native calculator demos.
  • WebView2 runtime — installed only when it is missing; spid3r gui programs need it (Windows 11 and Microsoft Edge already include it).
  • C++ Build Tools — downloads the MSVC Build Tools with the Windows SDK (~3 GB, needs administrator rights), which linking a native executable requires; skipped when already installed.
  • .matrix file association — double-clicking a .matrix file runs it with spid3r run.

Linux / macOS installer

A one-line installer (plain POSIX sh; curl or wget is the only requirement):

curl -fsSL https://raw.githubusercontent.com/needyamin/spid3r/main/install.sh | sh

The script detects your architecture (x86_64 / aarch64), downloads the matching release tarball from GitHub, installs spid3r into ~/.spid3r/bin, and adds that directory to your PATH in ~/.bashrc, ~/.zshrc, and ~/.profile (it never writes a line that is already there). Options: 

sh install.sh --version 1.0.0   # pin a release instead of latest
sh install.sh --dir ~/.local/bin

--dir and the SPID3R_INSTALL_DIR environment variable override the install location. Afterwards open a new terminal (or source ~/.bashrc) and verify with spid3r --version.

Backends

The webview GUI backend (spid3r gui) and the LLVM native backend (spid3r build) are part of the standard toolchain build and are described under Developer tools. GUI programs need the WebView2 runtime on Windows; linking a native executable needs the MSVC Build Tools with the Windows SDK. Everything else — run, check, compile, exec, test, fmt, debug, repl, lsp, bundle, and the package manager — works out of the box on both engines.

Quick start

Create hello.matrix:

fn main() {
    println("Hello, Spid3r!");
    return 0;
}

Run it on either engine, or compile it to bytecode and execute that:

spid3r run hello.matrix                 # tree-walk interpreter (default)
spid3r run --engine vm hello.matrix     # bytecode VM, same output
spid3r compile hello.matrix             # writes hello.matrixc
spid3r exec hello.matrixc               # runs the bytecode; no source needed
Hello, Spid3r!

A slightly bigger taste: closures, collections, and error handling.

fn make_counter() {
    let count = 0;
    return fn() {          // the closure captures `count`
        count += 1;
        return count;
    };
}

fn main() {
    let tick = make_counter();
    tick();
    println(tick());                                         // 2

    let xs = list(1, 2, 3, 4, 5);
    println(xs.filter(fn(x) { return x % 2 == 0; }));        // [2, 4]
    println(xs.reduce(0, fn(acc, x) { return acc + x; }));   // 15

    try { println(10 / 0); } catch (e) { println("caught: " + e); }   // caught: division by zero
    return 0;
}
TipUse spid3r repl to try snippets interactively, and spid3r check file.matrix to type- and visibility-check without running.

Program structure

  • A source file has the extension .matrix. It starts with any import statements, followed by declarations (fn, class, interface, let, const) and statements.
  • A program defines fn main(). spid3r run executes the top-level code in order, then calls main; a file without main is rejected with a program run by `spid3r run` needs fn main().
  • If main returns an int, that becomes the process exit code; any other return value exits with 0. An uncaught error exits with 1.
  • A file without main is a library module. It can be imported, and check / compile accept it.
import "math_util";          // imports come first

const GREETING = "hi";       // top-level declarations

fn main() {
    println(GREETING);
    return 0;                // process exit code
}

Syntax basics

  • Comments: // line comment and /* block comment */ (block comments do not nest). A UTF-8 BOM at the start of a file is tolerated.
  • Identifiers are ASCII and case-sensitive: a letter or _, then letters, digits, or _.
  • Variables: let x = 1; declares a mutable binding (the initializer is optional); const LIMIT = 3; declares an immutable one, and assigning to it is a semantic error (cannot assign to const 'LIMIT').
  • Statements end in ;, except block forms (if/elif/else, while, for, try, bare blocks) and fn / class / interface declarations. import "name"; ends in ;.
  • String escapes: \n \r \t \\ \". Any other escape is a lexer error.
Local functionsNamed fn helper(x) { … } declarations work both at the top level and inside any block without needing a trailing semicolon, and support local recursion. You can also bind anonymous function literals with let f = fn(x) { … };.

Reserved keywords

Keywords are lowercase and case-sensitive:

fn let const if elif else while for in break continue return
true false null and or not import try catch finally throw
class interface new self public private spawn async await extends implements
match enum

Type and constructor names (list, map, heap, …) and builtin functions are not keywords. They are ordinary globals and can be shadowed. See docs/KEYWORDS.md.

Values & types

Primitives: int (64-bit signed), float (64-bit IEEE), bool, string (immutable UTF-8), and null. Everything else is a built-in object: collections, option/result, class instances, functions, tasks, channels, and so on. type_of(x) returns a value's type name and string(x) converts it to text.

Truthiness

Used by if, while, and/or/not, and bool():

Value Truthy when
bool its own value
null never
int / float non-zero (0 and 0.0 are falsy)
string non-empty
option some(…); none is falsy
everything else: containers, result (including err(…)), tasks, instances always
Numeric semantics
  • int + float promotes to float; int / int truncates toward zero (7 / 2 is 3, -7 / 2 is -3).
  • Integer arithmetic wraps on overflow (i64): 9223372036854775807 + 1 is -9223372036854775808.
  • Division or modulo by zero throws division by zero.
  • 1 == 1.0 is true. An integer literal outside the i64 range is a lexer error.

Enums and match

An enum is a sum type: a value that is exactly one of its variants, each carrying its own fields. A match takes it apart, and the compiler checks that every variant is handled.

enum Shape {
    Empty,
    Circle(radius),
    Rect(w, h),
}

fn area(s) {
    return match (s) {
        Circle(r) => 3 * r * r,
        Rect(w, h) => w * h,
        Empty() => 0,
    };
}

Arms are tried in order. A pattern can be a variant (Circle(r)), a literal (0, "a"), a binding that captures the whole value (x), or _. Patterns nest (Dot(At(x, y))), and a if guard narrows an arm — a failed guard falls through to the next arm rather than failing the match:

return match (s) {
    Circle(r) if (r > 10) => "big",
    Circle(r) => "small",
    _ => "other",
};

A match with no _ or binding arm must cover every variant of the enum it names; spid3r check reports the missing ones. When the enum cannot be inferred (literals only), an unmatched value throws a normal runtime error instead.

Value-position if

if also works as an expression, so a conditional value needs no temporary and no statement dance. Each branch yields its last expression (a branch may omit that final ;); a missing else yields null. 

fn grade(n) {
    return if (n >= 90) { "A" } else if (n >= 80) { "B" } else { "C" };
}
let label = if (count == 0) { "empty" } else { "{count} items" };

return inside a branch returns from the enclosing function, not from the branch. The value forms are rewritten into a temporary plus ordinary statements before any engine runs, so all three engines agree by construction — and a statement that uses none of them is passed through untouched.

+ - * / %

== != < <= > >=

Logical

and or not (and/or short-circuit)

Bitwise

& | ^ << >> — int operands only; C precedence (& tighter than ^ tighter than |, all looser than a comparison). A shift amount outside 0..=63 is an error.

Unary

-x · not x · await x · spawn fn(){…}

x as int · x as float · x as string · x as bool — binds tighter than * and may chain; exactly the conversion builtins int()/float()/string()/bool().

Assignment (right-associative)

= += -= *= /= %=

Null handling

?? (fallback when null — the right side is evaluated only when the left is null) · obj?.field (null when the receiver is null)

Members & indexing

obj.field · obj.method() · xs[i] · xs[i] = v · m[k] = v

Construction

new Class(…) · [a, b] · (a, b, c) tuple literal · list(…) · fn(x){…}

Not available

No !, ++, ~, or **. Use not, x += 1, and pow(b, e). ^ is bitwise xor, not exponentiation.

Precedence, tightest first: postfix (call, index, field, method) → unary not / - / await / spawn → as casts → * / % → + - → << >> → comparisons → & → ^ → | → and → or → ?? → assignment. Comparison chains are left-associative (a < b < c parses as (a < b) < c), so write a < b and b < c instead. 

fn main() {
    println(10 + 0.5);        // 10.5   int + float -> float
    println(7 / 2);           // 3      int / int truncates
    println(7.0 / 2);         // 3.5    a float operand -> float
    println(7 % 3);           // 1
    println(2 * (3 + 4));     // 14
    println(true and false);  // false
    println(not true);        // false
    println(1 < 2 or 9 < 3);  // true
    let a = 5;
    a += 3;
    println(a);               // 8
    return 0;
}

Control flow

if / elif / else (else if is the same as elif), while, two forms of for (collection iteration and a C-style header), plus break and continue in every loop form. else always binds to the nearest unfinished if. 

fn main() {
    for x in [1, 2, 3] { println(x); }                 // 1 2 3
    for (k, v) in scores { println("{k}={v}"); }       // map entries
    for let k = 0; k < 3; k = k + 1 { println(k); }    // 0 1 2

    let i = 0;
    while i < 2 { println(i); i += 1; }                // 0 1

    let n = 2;
    if n == 2 { println("two"); }
    elif n == 1 { println("one"); }
    else { println("other"); }                         // two
    return 0;
}

for (k, v) in m walks a map's entries — k is the key and v its value. The one-variable form keeps its meaning (a map yields keys, a list yields elements), so the two forms are unambiguous.

Destructuring bindings

let can bind several elements of a list or tuple at once; the right-hand side is evaluated exactly once.

fn min_max(xs) {
    return [xs[0], xs[xs.len() - 1]];
}

let (lo, hi) = min_max([3, 1, 4]);
println("{lo}..{hi}");     // 3..4

What for … in iterates

Collection Yields
list, vec, vector, tuple, deque, queue, linked lists elements, front to back
bytes integer bytes (0..255)
stack elements, top first
ring_buffer current elements, oldest first
set · bag members in insertion order (a bag yields each occurrence)
map values, in insertion order (use keys() / items() for keys)
graph nodes
bst values in sorted (in-order) order
heap, binary_tree, trie stored values / words (internal order)
hash_table keys, in bucket order (not insertion order)
string one-character strings

matrix and priority_queue are not iterable; use row()/col() or repeated pop().

Functions & closures

Functions are first-class values. Anonymous fn(x) { … } literals nest and capture their surrounding bindings, and recursion is supported. async fn marks a function that may await; using await elsewhere is a semantic error. Trailing parameters may declare constant defaults (fn greet(name, greeting = "Hello")) — omitted trailing arguments are filled from them (functions, methods, and constructors alike); once one parameter has a default, every parameter after it must have one, and defaults must be literal numbers, strings, booleans, or null. Calls may also pass arguments by name (greet(greeting: "Hi", name: "ada")) on direct function calls, constructors, and super; positional arguments must come first, and parameters the call omits fall back to their defaults. 

fn make_adder(base) {
    return fn(x) { return x + base; };   // captures `base`
}

fn fact(n) {
    if n <= 1 { return 1; }
    return n * fact(n - 1);
}

fn main() {
    let add100 = make_adder(100);
    println(add100(5));   // 105
    println(fact(5));     // 120
    let g = fact;         // functions are values
    println(g(4));        // 24
    return 0;
}

Capture rules

These rules are identical on both engines and pinned by regression tests:

  • Closures capture bindings, not values. A write through one closure is visible to every other closure over the same binding.
  • for x in … creates a fresh binding per iteration. Closures made in iteration N see that iteration's value.
  • while and C-style for share one binding. Closures created there observe the variable's final value; bind a fresh let inside the body if you need a snapshot.
  • Every activation is isolated. Recursive functions and factories such as make_adder never leak state between calls. 
fn main() {
    let fs = list();
    for x in [0, 1, 2] { fs.push(fn() { return x; }); }
    println(fs.map(fn(f) { return f(); }));    // [0, 1, 2]

    let gs = list();
    let i = 0;
    while i < 3 { gs.push(fn() { return i; }); i += 1; }
    println(gs.map(fn(f) { return f(); }));    // [3, 3, 3]
    return 0;
}

Classes & interfaces

OBJECT MODEL

Class Inheritance & Interface Contract Hierarchy

Single class inheritance with multi-interface compliance, virtual method dispatch tables, and explicit self receiver.

  • Single inheritance with extends; methods resolve through the parent chain, so overrides dispatch polymorphically.
  • Visibility: members are private by default; mark them public to expose them. The semantic checker rejects out-of-class access to private members (field 'x' of class 'A' is private).
  • Receiver: self is an explicit parameter of every method.
  • Constructor: the method named new, invoked as new Class(…). The shorthand member new(params) { … } is also accepted. 
class Animal {
    public let name;
    private let noise;
    fn new(name, noise) { self.name = name; self.noise = noise; }
    public fn speak(self) -> string { return self.name + " says " + self.noise; }
}

class Dog extends Animal {
    fn new(name) { self.name = name; self.noise = "woof"; }
    public fn fetch(self) -> string { return self.name + " fetches"; }
}

fn main() {
    let d = new Dog("Rex");
    println(d.speak());    // Rex says woof   (inherited from Animal)
    println(d.fetch());    // Rex fetches
    // println(d.noise);   // semantic error: private member
    return 0;
}

Interfaces declare method signatures (each ending in ;), and classes opt in with implements A, B. Dispatch is by method name, so a variable may hold any implementation. 

interface Named {
    fn name(self) -> string;
}

class Team implements Named {
    public let label;
    fn new(label) { self.label = label; }
    public fn name(self) -> string { return "team-" + self.label; }
}

fn main() {
    println(new Team("core").name());   // team-core
    return 0;
}

Printing an instance shows its class and field map, e.g. Dog {name: Rex, noise: woof}. Field order in that output is not guaranteed.

Error handling

Errors are values. throw raises any value, and try / catch (e) / finally handles it. At least one of catch or finally is required. An uncaught error prints its message, source position, and a call-stack trace, then exits with code 1: 

error[runtime]: uncaught throw (thrown: bad)
  --> app.matrix:1:13
  |
1 |     throw "bad";
  |     ^^^^^^^^^^^
  stack trace (most recent call first):
    at boom (app.matrix:1:13)
    at main (app.matrix:3:5)

Every diagnostic shows the offending line with a caret under the span, then any = note: / = help: lines. A type mismatch, for example, suggests the fix: 

error[semantic]: type mismatch in 'xs': expected list<int>, got list<string>
  --> app.matrix:2:25
  |
2 |     let xs: list<int> = ["a"];
  |                         ^^^^^
  = help: annotations are checked before the program runs; use `any` to opt out,
          or convert explicitly with string(x) / int(x) / float(x)

spid3r check --json file.matrix prints the same diagnostic as one JSON object (phase, message, file, line, col, len, help, notes, trace) for editors and CI.

Lint warnings

spid3r check also reports things that are suspicious rather than wrong. Warnings never change the exit code unless you ask them to:

Lint Reports
unused-variable A local that is never read.
unused-parameter A parameter that is never read. Name it _req when a callback must match a signature it does not use.
unused-import An import whose names are never used.
unreachable-code A statement after return, throw, break, or continue. 
warning[semantic]: unused parameter 'req'
  --> app.matrix:13:16
   |
13 |     app.use(fn(req) {
   |                ^^^

--deny-warnings makes any warning fail the build (exit 1), and --allow unused-parameter silences one lint without hiding the rest. In --json mode each warning carries "severity":"warning" and its "lint" name.

Option and result

Two sum types model expected failure without throwing:

Type Constructors Methods
option some(v), none is_some, is_none, unwrap (throws on none), unwrap_or(d), map(f), and_then(f), ok_or(e), unwrap_or_else(f), flatten
result ok(v), err(e) is_ok, is_err, unwrap (throws on err), unwrap_or(d), unwrap_err, map(f), map_err(f), and_then(f), unwrap_or_else(f), flatten

An option or result can be annotated — let x: option<int> = some(5) — and collection annotations check their element type, so let xs: list<int> = ["a"] is rejected.

The ? operator

expr? returns the failure from the enclosing function and yields the payload otherwise. It works on both option and result, so a chain of fallible calls needs no nesting:

fn half(n) {
    if (n % 2 != 0) { return err("odd"); }
    return ok(n / 2);
}

fn quarter(n) {
    let h = half(n)?;        // returns err("odd") to the caller
    return ok(h / 2);
}

quarter(8);   // ok(2)
quarter(3);   // err(odd)

On an option it propagates none. It is implemented as if (is_failure(v)) { return v; } v.unwrap(), and is_failure is a normal builtin, so the same check is available directly. 

fn parse_age(s) {
    let n = int(s);
    if n < 0 { return err("age cannot be negative"); }
    return ok(n);
}

fn main() {
    try { println(10 / 0); }
    catch (e) { println("caught: " + e); }       // caught: division by zero
    finally { println("done"); }                 // done

    let r = parse_age("42");
    if r.is_ok() { println("ok: " + string(r.unwrap())); }   // ok: 42

Strings

Strings are immutable UTF-8. Lengths and indexes count characters, not bytes. Indexing s[i] returns a one-character string. Negative indices count from the end — s[-1] is the last character, and xs[-1] the last element of a list — on lists, tuples and strings. + concatenates two strings only; convert other values with string(x) or use format ("a" + 1 throws cannot add string and int).

Interpolation. A literal may contain {name} or {obj.field} holes — no whitespace inside the braces. Each hole is converted with string(...), so no explicit conversion is needed: 

let name = "ada";
let n = 36;
println("hi {name}, {n} years");   // hi ada, 36 years

Anything else starting with { is literal text, so "{{ user }}", "{ x }", "{}" and "{0}" stay exactly as written — the stdlib template engine relies on that. A hole is recognised only when { is followed immediately by an identifier.

A comparator cmp(a, b) may answer a bool (true = a comes first) or a number (negative / zero / positive). Sorts are stable: equal elements keep their input order. Concurrency

CONCURRENCY ENGINE

Task Concurrency & FIFO Channel Message Passing

Lightweight asynchronous worker tasks communicate cleanly over buffered or unbuffered channels on a work-stealing thread-pool scheduler.

spawn fn() { … }; runs a function literal as a task on a threaded scheduler and returns a task. await joins a task or receives one message from a channel, and is only legal inside an async fn.

Tasks

Member Behavior
await t (in async fn) Join the task and return its value; a failed task re-raises its error to the awaiter.
t.join() Block until finished and return the value, or re-raise the failure. A thrown value crosses the boundary as the value, so catch rebinds the original map/object rather than a string. Repeatable: joining twice returns the same value.
t.status() "running", "done", or "failed". Never blocks.
t.is_done() Non-blocking completion check.

A task that throws does not crash the program. The error is stored, status() becomes "failed", and the error is re-raised on join/await, so the joining side can try/catch it.

Shared state

Constructor Methods & semantics
channel() Unbounded FIFO queue. send(v) never blocks; recv() blocks until a message arrives; try_recv() returns an option; also len, is_empty. await ch receives one message.
mutex(v) lock() blocks until the mutex is free, then returns the inner value (collections are aliased, so mutations stick). Release it explicitly with unlock().
ref(v) A shared mutable cell: get(), set(v). 
async fn settle(t) { return await t; }

fn main() {
    let ch = channel();
    spawn fn() { ch.send(1); ch.send(2); };
    println(ch.recv());                   // 1
    println(ch.recv());                   // 2

    let t = spawn fn() { return 7; };
    println(settle(t));                   // 7

    let bad = spawn fn() { throw "task-error"; };
    sleep_ms(30);
    println(bad.status());                // failed
    try { bad.join(); } catch (e) { println("caught " + e); }   // caught task-error

    let shared = mutex(list());
    let items = shared.lock();
    items.push(1);
    shared.unlock();
    return 0;
}

Related builtins: task_count(), sleep_ms(n), yield(), and spawn_process(cmd, args) (synchronous; see the standard library).

Scheduler & resource limits

Tasks run on a process-wide pool that starts at the machine's CPU count and grows on demand, so a task parked in recv, join, mutex.lock, or sleep_ms never starves work that is waiting behind it.

Aspect Behavior
Workers One worker per outstanding task, up to SPID3R_MAX_WORKERS (default 256); extra workers retire after 10 s idle. At the ceiling a stall is reported on stderr with the variable to raise instead of hanging silently.
Ready queue Bounded by SPID3R_QUEUE_CAP (default 65536 jobs). spawn grows the pool first and then blocks the producer until a worker takes a job, so a spawn storm cannot exhaust memory and no task is dropped.
Program exit Waits up to SPID3R_TASK_DRAIN_MS (default 2000 ms) for tasks main left running — their output is not lost — then reports what is still running and exits 0. The worker threads are then joined, not killed mid-write.
gc_collect() Runs only when no other thread is executing Spid3r code; tasks parked in a blocking wait hold their values on their own stacks and do not block a collection. While another thread is genuinely running it fails with a clean, catchable error.

import "tz";
import "unicode";

fn main() {

    tz_add_days("Europe/Berlin", ts, 1);       // same wall clock across a DST change
    tz_http_date(1761000000);                  // "Mon, 20 Oct 2025 22:40:00 GMT"

    // Unicode: canonical equivalence and case folding are real now.
    unicode_equal("é", "e" + chr(769));        // true
    unicode_casefold("straße");                // "strasse"
    unicode_caseless_equal("STRASSE", "straße"); // true

Memory model & GC

MEMORY MANAGEMENT

Cycle-Collecting Garbage Collector Design

Spid3r uses immediate reference counting for deterministic, zero-pause destruction of acyclic objects, paired with an on-demand cycle-detecting collector to reclaim cyclic garbage graphs.

Values are reference-counted and internally synchronized. Both engines share this representation, which is what lets values cross spawn boundaries. Acyclic garbage is freed as soon as the last reference drops.

Full-container cycle collectionA reference cycle (a list containing itself, an object pointing at itself, a graph or tree storing a parent container, or two maps referencing each other) never reaches a zero refcount on its own. Spid3r's trial-deletion cycle collector automatically tracks and reclaims cycles across all 20+ built-in containers and class instances (list, vec, stack, queue, deque, linked_list, set, map, hash_table, bag, ring_buffer, binary_tree, bst, heap, priority_queue, graph, trie, matrix, ref, option/result wrappers, and class instances). It runs automatically at statement boundaries (on by default; set SPID3R_GC=0 to disable). gc_collect() forces a pass (it refuses with a clean error while another thread is running Spid3r code — parked tasks hold their values on their own stacks and do not count), gc_live_cells() inspects the tracked heap, and weak(v) / deref(w) provide explicit non-owning references when desired. Design notes: docs/GC.md. 
fn main() {
    let before = gc_live_cells();
    {
        let l = list(1, 2, 3);
        l.push(l);                           // a cycle
    }
    gc_collect();
    println(gc_live_cells() <= before);     // true: the cycle was reclaimed
    return 0;
}

Projects & dependencies

spid3r init myproj creates a project; spid3r run with no file then runs its entry. 

# spider.toml
[package]
name = "myproj"
version = "0.1.0"
entry = "src/main.matrix"      # what `run` (no file) and `dist` use

[dependencies]
mathlib = { path = "../mathlib" }                            # path dependency
extras  = { git = "https://example/extras", rev = "main" }   # git dependency
serde   = { version = "^1.0" }                               # local registry ($SPID3R_REGISTRY)
  • Install: spid3r install vendors each dependency's sources into vendor/<name>/ and writes a deterministic spider.lock. A re-install reproduces the commit recorded there, so a moving branch cannot drift under you; spid3r install --update is the explicit way to move to a newer upstream commit. Every vendored tree is hashed over every file under src/ as raw bytes (path NUL contents NUL, sorted, / separators). Re-running is idempotent; a tampered or stale vendor/ tree is re-synced.
  • Git transports: a manifest may point at https://, ssh://, or scp-like user@host:path URLs. Local paths and file:// require SPID3R_ALLOW_LOCAL_GIT_DEPS=1; plaintext http:///git:// require SPID3R_ALLOW_INSECURE_GIT=1; git's ext:: "run this command" transport is rejected outright, because a dependency manifest must never be able to execute a command during install.
  • Version constraints: ^1.0 (same major), >=1.2, =1.2.3, or an exact version, checked against the dependency's own manifest.
  • Local registry: { version = "…" } resolves from $SPID3R_REGISTRY, an offline directory of <name>/<version>/ packages. A package may ship dist/sha256.txt; install verifies the vendored tree against it, and spid3r pack prints the matching line. The hash covers every file under src/ as raw bytes (regenerate a sha256.txt produced before 2026-10-21: the older construction skipped non-.matrix files and decoded contents lossily).
  • Workspaces: [workspace] members = […] share one vendor/ and lockfile, with name-conflict detection.
  • Distribution: dist builds a self-contained target/<package>.matrixc; pack/unpack move source projects as deterministic POSIX ustar tarballs (supporting long paths via the 155-byte ustar prefix and GNU @LongLink headers, with header checksum verification).
  • Tests: inside a project, spid3r test differentially runs tests/*.matrix per member. Use assert/assert_eq so failures explain themselves.

There is no remote/HTTP registry, and registry packages' own dependencies are not resolved transitively, so declare everything you use. See docs/REGISTRY.md.

3 spid3r debug session ended with quit
n spid3r run: the integer returned by main

Diagnostics name their phase and position, e.g. error[semantic]: … --> file.matrix:3:20.

Bytecode VM & .matrixc

The compiler lowers the checked AST into a compact Chunk: code bytes plus constant, function, and class pools, with per-instruction spans for error messages. Closures carry heap upvalue cells: captured locals route reads and writes through a shared cell created fresh per activation, loop iterations re-capture per-iteration bindings, and scope exits release the routing. Together these keep closures correct across recursion, loops, and spawned tasks.

File format

compile writes a serialized script function (little-endian) that starts with a magic header, so foreign or corrupt files are rejected with a clean diagnostic:

.matrixc       ::= b"SPID3R"  version:u16  VmFunc        # current version: 1

VmFunc         ::= name:str?  arity:u64  is_async:u8
                   upvalue_slots:u8[]  own_upvalues:u8  Chunk
Chunk          ::= code:bytes
                   constants:value[]          # scalars only: 0=int 1=float 2=string
                   functions:VmFuncProto[]
                   classes:VmClassProto[]
                   inst_offsets:u64[]   inst_spans:Span[]
                   modules:embedded[]         # imports, keyed by resolved path
EmbeddedModule ::= key:str  public:str[]  VmFunc
SafetyBefore a chunk runs, it is validated. Opcodes are decoded through a safe lookup (no unchecked casts), and the validator rejects invalid opcodes, truncated instructions, out-of-range constant/function/class references, jump targets that miss an instruction boundary (found by binary search, so validation stays O(n log n)), an empty code section, a chunk that can fall through its last instruction (it must end in return/throw/jump), and instruction metadata that disagrees with the code (inst_offsets and inst_spans must have equal length, increase strictly, and stay inside the code). The deserializer additionally rejects trailing bytes and caps function/module nesting at 128. Pool reads, jump targets, and the VM's instruction fetch are bounds-checked at run time, so bad bytecode becomes a runtime error, never a panic.

Optimizer

On by default (--no-opt disables it):

  • Constant folding reuses the interpreter's own arithmetic, so folded results and errors match exactly (1/0 is never folded).
  • Peephole cleanup: Jump +0, push-then-pop.
  • Static branch folding and dead-code elimination (skipped inside try chunks).

Full reference: docs/BYTECODE.md.

Testing & QA

Because correctness means the engines agree, Spid3r is verified differentially. As of this revision, the test suite passes 685 tests (669 without the optional backends, plus 10 GUI and 6 AOT tests), and spid3r test reports 25 ok, 0 failed over the 25 examples/*.matrix files (24 programs + 1 shared library module). The counts come from tools/count_tests.sh, which queries the test runner directly rather than grepping, so the documentation cannot drift from reality.

  • spid3r test classifies each examples/*.matrix by its parsed AST (a file with fn main is a program, anything else is a library). Programs run on the tree interpreter, the VM, and compile + exec, and all three stdout streams must match. Libraries are semantic-checked.
  • The test suite runs unit tests per subsystem, integration tests, the differential harness (tests/difftest.rs), property/mutation fuzz suites (tests/fuzz_tests.rs), and dedicated engine-parity regressions (tests/audit_regressions.rs). The regressions cover closure capture, per-iteration loop bindings, scope-exit slot release, nested upvalue descriptors, local named fn declarations, finally on return/break/continue, cycle-safe container display/equality/cloning, full-container cycle collection, self-argument collection operations, map index assignment, file-op results, the task API, JSON round-trips, ustar long-path archiving, and RNG bounds.
  • tools/difftest.sh is a standalone shell version of the three-way comparison.
  • Bytecode safety & fuzzing are tested automatically: invalid opcodes, truncation, huge count headers, out-of-range pool references, negative jumps, off-boundary jumps, trailing bytes, mismatched instruction tables, fall-through chunk ends and over-deep nesting are all rejected cleanly (tests/artifact_hardening.rs), backed by deterministic mutation tests (tests/fuzz_tests.rs) and three fuzz targets (fuzz/) that a nightly CI workflow actually runs.
  • GUI is tested headlessly: IPC decoding, JSON escaping and round-trips, event ordering, unknown-event dropping, payload fidelity, and queued JS (bridge unit tests plus the spid3r gui --dry-run replay). The native window itself is exercised manually.

Enforced in cross-platform GitHub Actions CI (.github/workflows/ci.yml) plus a nightly fuzz workflow (.github/workflows/fuzz.yml). See _dustbin/AUDIT_REPORT.md.

Limitations & roadmap

Known limitations

  • Lexer: float literals accept scientific notation (1.5e3, 2E+4); -9223372036854775808 cannot be written as a positive integer literal before unary negation.
  • Native backend: a class declared inside a function is rejected with a clean diagnostic; everything else, including higher-order collection methods (list.map(f)), compiles.
  • Concurrency: a task blocked in recv/join/mutex occupies a worker, so more than SPID3R_MAX_WORKERS (256) such tasks at once can still stall — the watchdog reports it with the variable to raise — and the ready queue is capped at SPID3R_QUEUE_CAP (65536) with producer backpressure. Removing the ceiling entirely needs M:N scheduling with continuations.
  • Dependencies: local only (path, git, or offline registry); no transitive resolution of registry packages.
  • Known open (tracked in _dustbin/AUDIT_REPORT.md): closure/environment cycles are not collected (value containers and class instances are), cloning a cyclic value aliases the original into the copy, the regex engine restarts its NFA at each input index (O(n²·states)), net.rs buffers grow without compaction on a hostile chunked response, and deeply recursive containers abort while dropping.
  • Documented design choices: integer overflow wraps silently, int / int truncates, err(…) is truthy, comparison chains are left-associative, and assignments are legal in if/while conditions.
