Spid3r

A small, dynamically typed language that runs on a Rust host — with a tree-walking reference interpreter and a bytecode compiler + stack VM that are verified to agree. Plain English keywords, real semantics: closures, classes, modules, tasks, 20+ builtin data structures.

two engines: tree-walk & VM bytecode compile → exec task-based concurrency zero runtime dependencies 250 tests · 23/23 differential language v1.0
Get started CLI reference

1. What is Spid3r

Spid3r uses plain lowercase keywords (fn, let, class, spawn, import) but has real semantics: dynamic types, closures with upvalues, single-inheritance classes with interfaces, structured error handling, modules with visibility, task-based concurrency, a standard library, and a full suite of data structures. The whole tree — src/ — is pure Rust with no third-party dependencies.

Two engines, one front end
Walks the tree or runs bytecode; the lexer, parser and type/visibility checker are shared, and differential tests pin the engines to identical behavior.
Self-contained bytecode
compile embeds imported modules (keyed by resolved path) so exec runs with no source on disk.
Differentially tested
Every example runs three ways — tree, VM, and compile+exec — with identical stdout; a 27-program audit probe suite covers edge semantics.
Task concurrency
spawn/await, channel, mutex, ref on a threaded scheduler; tasks report status() and join repeatedly.
Data-structure suite
Lists, maps, sets, stacks, queues, heaps, tries, trees, graphs, matrices, ring buffers, bags — with higher-order list methods.
Validated bytecode
Chunks are validated before execution; bad opcodes or truncated code fail cleanly, never panic.

2. Architecture

Both engines share a single front end and a single value layer, which is what keeps them behaviorally identical.

.matrix source→ lexer→ parser → AST→ semantic checker→ tree-walk interpreter  or  compiler → bytecode VM
  • value::collections implements every value operation (construct, method dispatch, indexing, iteration, equality, display) once; both engines call it.
  • The compiler emits a clox-style Chunk; the VM is a register-free stack machine where each call frame's slots is both operand stack and locals. Captured locals live in per-activation heap cells, so closures are correct across recursion, repeated calls, loop iterations, and spawned tasks.
  • Differential testing (§22) proves the outputs match; the 2026-10 audit (see §22) closed the last known engine divergences around closures.

3. Build & quick start

Requires a Rust toolchain (edition 2021). From the crate root:

cargo build                 # debug binary   → target/debug/spid3r(.exe)
cargo build --release       # optimized      → target/release/spid3r(.exe)
cargo test                  # unit + integration + differential tests

30-second tour

// hello.matrix — the smallest Spid3r program.
fn main() {
    println("hello");
    return 0;
}
$ spid3r run hello.matrix
hello
$ spid3r run --engine vm hello.matrix     # same output on the bytecode VM
hello
$ spid3r compile hello.matrix             # writes hello.matrixc
$ spid3r exec hello.matrixc               # runs the bytecode, no source needed
hello

A taste of the language — closures, collections, classes, and error handling:

class Animal {
    public let name;
    private let noise;
    fn new(name, noise) { self.name = name; self.noise = noise; }
    public fn speak(self) -> string { return self.name + " says " + self.noise; }
}

fn main() {
    let adder = fn(x) { return x + 100; };
    println(adder(5));                        // 105

    let orders = stack();
    orders.push("review"); orders.push("merge");
    println(orders.pop());                    // merge

    println(new Animal("Rex", "woof").speak());  // Rex says woof

    try { print(10 / 0); } catch (e) { println("caught: " + e); }
    return 0;
}

5. Syntax basics

  • Comments: // line comment and /* block comment */ (block comments do not nest). A UTF-8 BOM at the start of a file is tolerated.
  • Identifiers are ASCII: start with a letter or _, continue with letters/digits/_; case-sensitive.
  • Keywords are reserved, lowercase, case-sensitive (a keyword inside a string is just text): fn let const if elif else while for in break continue return true false null and or not import try catch finally throw class interface new self public private spawn async await extends implements. Type/constructor names (list, map, heap, …) are not keywords — they are ordinary globals and can be shadowed.
  • String escapes: \n \t \\ \". Any other escape is a lex error.
  • Statements end in ; — except block-bearing forms (if/elif/else, while, for, try, blocks) and top-level declarations (fn, class, interface; import ends in ;). known quirk a fn declaration inside a block currently parses as an expression statement and needs a trailing ;; prefer let f = fn(x) { … }; for local functions.
  • Dynamic typing with optional gradual annotations (§17).

6. Values, types & truthiness

Primitives: int (64-bit signed), float (64-bit IEEE), bool, string (immutable, UTF-8), null. Everything else is a builtin object (collections, options/results, classes/instances, tasks, channels, …). Use type_of(x) for a value's type name and string(x) to stringify.

Truthiness (used by if, while, and/or/not, bool())

ValueTruthy when
boolits own value
nullnever
int / floatnon-zero (0, 0.0 are false)
stringnon-empty
optionsome(…) (none is false)
everything else — containers, result, tasks, instancesalways true
Numeric details. int + float promotes to float, but int / int truncates toward zero (7 / 2 is 3; -7 / 2 is -3). Division or modulo by zero throws. Integer arithmetic wraps on overflow (i64 semantics) — 9223372036854775807 + 1 is -9223372036854775808. An integer literal outside i64 range is a clean lex error. 1 == 1.0 is true.

There is no !, no ++, no **/^ — use not, x += 1, and pow(b, e).

Precedence (tightest first): postfix (call · index · field · method) → unary not/-/await/spawn → * / % → + - → comparisons → and → or → assignment (right-associative). Comparison chains are left-associative (a < b < c parses as (a < b) < c) — prefer a < b and b < c.

fn main() {
    println(10 + 0.5);        // 10.5   int + float -> float
    println(7 / 2);           // 3      int / int truncates
    println(7.0 / 2);         // 3.5    a float operand -> float
    println(7 % 3);           // 1
    println(2 * (3 + 4));     // 14
    println(true and false);  // false
    println(not true);        // false
    println(1 < 2 or 9 < 3);  // true
    let a = 5; a += 3;
    println(a);               // 8
    return 0;
}

8. Control flow

if / elif / else, while, two forms of for (iterate a collection, or a C-style header), and break / continue. else always binds to the nearest unfinished if.

fn main() {
    for x in [1, 2, 3] { println(x); }                // 1 2 3
    for let k = 0; k < 3; k = k + 1 { println(k); }   // 0 1 2

    let i = 0;
    while i < 2 { println(i); i += 1; }               // 0 1

    let n = 2;
    if n == 2 { println("two"); }
    elif n == 1 { println("one"); }
    else { println("other"); }                        // two
    return 0;
}

What for iterates: lists, vecs, tuples, deques, ring buffers, stacks (top first), queues, sets, bag members, map values (insertion order), matrix cells (row-major), graph nodes, and string characters. break/continue work in all three loop forms.

9. Functions & closures

Functions are first-class values and may be anonymous fn(x){…} expressions. Recursion, nesting, and capturing are all supported. async fn marks a function that awaits — a non-async function that uses await is a semantic error.

fn make_adder(base) {
    return fn(x) { return x + base; };   // captures `base`
}
fn fact(n) {
    if n <= 1 { return 1; }
    return n * fact(n - 1);              // recursion
}
fn main() {
    let add100 = make_adder(100);
    println(add100(5));   // 105  (closure kept its captured value)
    println(fact(5));     // 120
    let g = fact;         // functions are values
    println(g(4));        // 24
    return 0;
}

Capture rules (identical on both engines)

  • Mutation is visible. Closures capture the binding: a closure that writes a captured variable, and later reads through another closure over the same binding, see each other's writes.
  • for x in … rebinds per iteration. Closures created in iteration N capture that iteration's value: pushing three closures over [0, 1, 2] yields 0, 1, 2.
  • while and C-style for share one binding. Closures created there all observe the final value of the loop variable — bind a fresh let inside the body when you need per-iteration snapshots.
  • Every activation of a closure gets its own captured state: recursive functions and factories like make_adder never leak state between calls.
Local functions. A fn declaration inside a block currently parses as an expression statement and needs a trailing ; — bind local functions with let f = fn(x) { … }; instead. Top-level fn declarations never need a semicolon.

10. Classes & interfaces

Classes support single inheritance (extends) and interfaces (implements). Fields and methods are public (reachable from outside) or private (the default) — the semantic checker rejects out-of-class access to private members. self is the explicit receiver parameter of every method; the constructor is the method named new, invoked with new Class(...) (a shorthand new(params) { … } member is also accepted). Methods resolve through the parent chain, so overrides dispatch polymorphically.

class Animal {
    public let name;
    private let noise;
    fn new(name, noise) { self.name = name; self.noise = noise; }
    public fn speak(self) -> string { return self.name + " says " + self.noise; }
}
class Dog extends Animal {
    fn new(name) { self.name = name; self.noise = "woof"; }
    public fn fetch(self) -> string { return self.name + " fetches"; }
}
fn main() {
    let d = new Dog("Rex");
    println(d.speak());    // dog overrides Animal::speak
    println(d.fetch());    // Rex fetches
    // println(d.noise);   // semantic error: private member
    return 0;
}

Interfaces declare method signatures (each ends with ;); classes opt in with implements. Dispatch is by method name, so a variable may hold any implementation.

interface Named {
    fn name(self) -> string;
}
class Team implements Named {
    public let label;
    fn new(label) { self.label = label; }
    public fn name(self) -> string { return "team-" + self.label; }
}
fn main() {
    let t = new Team("core");
    println(t.name());   // team-core
    return 0;
}

11. Error handling

Errors are values. throw raises any value; try / catch (e) / finally catch it (finally always runs, even on return from inside try or catch; at least one of catch/finally is required). Uncaught errors print a message with source position and a call-stack trace, and exit with code 1.

Two sum types model expected failure without throwing:

TypeConstructorsMethods
optionsome(v), noneis_some, is_none, unwrap (throws on none), unwrap_or(d)
resultok(v), err(e)is_ok, is_err, unwrap (throws on err), unwrap_or(d), unwrap_err
fn parse_age(s) {
    let n = int(s);
    if n < 0 { return err("age cannot be negative"); }
    return ok(n);
}
fn main() {
    try { print(10 / 0); }                    // dividing by zero throws
    catch (error) { eprint("caught: " + error); }
    finally { println("done"); }              // done

    let r = parse_age("42");
    if r.is_ok() { println("ok: " + string(r.unwrap())); }   // ok: 42

    let bad = parse_age("-1");
    println(bad.is_err());                    // true

    let none_val = none;
    try { none_val.unwrap(); }                // unwrap on none throws
    catch (e) { println("caught: " + e); }    // caught: unwrap on none
    return 0;
}
Convention. File and process builtins (read_file, write_file, spawn_process) return result values — branch with is_ok/is_err instead of try. Argument and type errors (e.g. write_file(1, "x")) still throw.

Strings are immutable UTF-8 values with a dot-method suite. Indexes and lengths are in characters, not bytes.

    println("a={} b={}".format(1, "two"));   // a=1 b=two

14. Modules

import "name"; loads another file; only members marked public are exported (privacy is enforced by the semantic checker). Imports must appear before other declarations. Names resolve next to the importing file first, then along SPID3R_PATH, vendored vendor/ dependencies, and ./stdlib.

// math_util.matrix  — a library module (no fn main)
public fn square(x) { return x * x; }
public const LIMIT = 3;
fn secret()         { return 42; }     // private: not exported

// modules.matrix  — the program
import "math_util";
fn main() {
    println(square(5));   // 25
    println(LIMIT);       // 3 (public const is immutable in the importer)
    return 0;             // calling secret() here is a semantic error
}
  • One instance per file. A module is identified by its resolved path (canonicalized), so import "lib/util" and import "./lib/util" share one instance; its top-level code runs exactly once.
  • Cycles are detected with a clear diagnostic that prints the full chain (circular import of 'a' (chain: main → a → b → a)) — never a hang.
  • Compile-time resolution errors (module not found) are semantic errors with source positions.
Self-contained bytecode. When you compile the program, every imported module (and its transitive imports) is resolved, checked, and embedded into the .matrixc file, keyed by resolved path. Running exec therefore needs no .matrix source on disk.

15. Concurrency

spawn fn(){…}; runs a function as a task on a threaded scheduler and returns a task. await either joins a task or receives one message from a channel — and is only legal inside an async fn. Shared state uses channel() (unbuffered), mutex(v) (a RAII guard via lock()), and ref(v) (a simple cell: get() / set()).

The task API

MemberBehavior
await t (in async fn)Join the task: returns its value; a failed task re-raises its error to the awaiter.
t.status()"running" · "done" · "failed" — never blocks.
t.join()Block until finished, return the value (or raise the task's error). Repeatable: joining twice returns the same value.
t.is_done()Non-blocking finished check.

A task that throws does not crash the program: the error is stored, shown by status() == "failed", and re-raised when you join/await — so you can try/catch it on the joining side.

async fn settle(t) { return await t; }

fn main() {
    let ch = channel();
    spawn fn() { ch.send(1); ch.send(2); };
    println(ch.recv());                   // 1
    println(ch.recv());                   // 2

    let t = spawn fn() { return 7; };
    println(settle(t));                   // 7

    let bad = spawn fn() { throw "task-error"; };
    sleep_ms(30);
    println(bad.status());                // failed
    try { bad.join(); } catch (e) { println("caught " + e); }  // caught task-error
    return 0;
}

Channel methods: send(v), recv() (blocks), try_recv(), state(), len(). Also available: task_count(), sleep_ms(n), yield(), and spawn_process(cmd, args) (synchronous, returns ok(exit_code) / err(msg), passes argv directly — no shell).

17. Gradual typing

Annotations are optional everywhere — unannotated code stays fully dynamic — but when present they are enforced by spid3r check and before every run:

fn add(a: int, b: int) -> int {
    return a + b;
}
let count: int = 0;
let name: string = "spid3r";

class Point {
    public let x: float;
    public let y: float;
    fn new(x: float, y: float) { self.x = x; self.y = y; }
}
  • Checked positions: let/const bindings, parameters, return types, and class fields.
  • int widens to float; any opts out for a binding.
  • Mismatched assignment, call arguments, returns, and field writes are rejected at compile time with positions — before any code runs.

18. Bytecode VM & the .matrixc format

The compiler lowers the checked AST into a compact, clox-style Chunk — code bytes plus constant, function, and class pools, with per-instruction spans for error messages. The VM is a register-free stack machine: each call frame's slots is both its operand stack and its locals. Closures carry heap upvalue cells: captured locals of a frame route reads/writes through a shared cell, the cell is created fresh per activation, loop iterations re-capture per-iteration bindings, and scope exits release the routing — together these keep closures correct across recursion, loops, and spawned tasks, with semantics identical to the tree engine. Every value operation (construct, method dispatch, indexing, iteration, equality, display) is delegated to the shared value::collections layer.

compile writes a .matrixc — a serialized script function, little-endian, beginning with a magic header so corrupt files are rejected with a clean diagnostic instead of a crash:

.matrixc      ::= b"SPID3R"  version:u16  VmFunc

VmFunc         ::= name:str?  arity:u64  is_async:u8
                   upvalue_slots:u8[]  own_upvalues:u8  Chunk
Chunk          ::= code:bytes
                   constants:value[]          # scalars only: 0=int 1=float 2=string
                   functions:VmFuncProto[]
                   classes:VmClassProto[]
                   inst_offsets:u64[]   inst_spans:Span[]
                   modules: embedded[]        # imports, keyed by resolved path
EmbeddedModule ::= key:str  public:str[]  VmFunc

Safety. Before a chunk runs, it is validated: opcodes are decoded through a safe lookup (no mem::transmute), and the validator rejects invalid opcodes, truncated instructions, out-of-range constant/function/class references, and jump targets that don't land on an instruction boundary. Pool reads and jumps are bounds-checked at run time too, so stack underflow and bad jumps become runtime errors — never panics.

Optimizer. On by default (--no-opt to disable): constant folding reuses the interpreter's own arithmetic so folded results and errors match exactly (1/0 is never folded), peephole cleanup (Jump +0, push-then-pop), static branch folding, and dead-code elimination (skipped inside try chunks).

Full reference: docs/BYTECODE.md.

19. Projects & dependencies

spid3r init myproj scaffolds a project: a spider.toml manifest (named from the directory), src/main.matrix, and a .gitignore.

# spider.toml
[package]
name = "myproj"
version = "0.1.0"
entry = "src/main.matrix"      # what `spid3r dist` / `run` (no file) builds

[dependencies]
mathlib  = { path = "../mathlib" }             # path dependency
extras   = { git = "https://example/extras", rev = "main" }   # git dependency
serde    = { version = "^1.0" }                # local registry ($SPID3R_REGISTRY)
  • spid3r install vendors every dependency's src/ into vendor/<name>/ and writes a deterministic spider.lock (git deps are pinned to the resolved commit; every vendored file is covered by a SHA-256 tree hash). Re-running is idempotent; a tampered or stale vendor/ tree is re-synced.
  • Version constraints: ^1.0 (same major), >=1.2, =1.2.3, or exact — checked against the dependency's own manifest.
  • Local registry: { version = "…" } dependencies resolve from $SPID3R_REGISTRY, an offline directory of <name>/<version>/ packages. A package may ship dist/sha256.txt; install verifies the vendored tree against it, and spid3r pack prints the matching sha256(tree) line to paste there.
  • Workspaces: [workspace] members = […] share one vendor/ and lockfile, with name-conflict detection.
  • Distribution: spid3r dist compiles the manifest entry into a self-contained target/<package>.matrixc; pack/unpack move source projects as deterministic, path-traversal-guarded tarballs.
  • Project-aware commands: run (no file) runs the manifest entry; test differentially runs tests/*.matrix per member — use the assert/assert_eq builtins so failures are self-explanatory.

There is no remote/HTTP registry and registry packages' own dependencies are not resolved transitively — declare what you use. See docs/REGISTRY.md.

20. fmt · bench · debug · gui · native

spid3r fmt
Canonical formatting in place; machine-checked invariants (re-lexes to the identical token stream, idempotent), comment and literal preservation, line wrapping. --check exits 1 when a file differs — wire it into CI.
spid3r bench
Times benchmarks/*.matrix, best-of-N (--runs), per engine (--engine tree|vm); --compare also asserts tree == vm output, so benchmarks double as differential tests.
spid3r debug
Line debugger over the VM: --break 3,7 breakpoints, step/next/finish, backtrace, locals, source listing. Fully scriptable via --commands FILE for repeatable sessions.
spid3r gui gui feature
Desktop webview window (wry + tao). The program builds UI with gui_set_html(html), gui_eval(js), registers handlers with gui_on(event, fn), can push events with gui_emit(event, payload); the page calls back via window.spid3r.emit(event, payload). --dry-run replays the whole bridge headlessly (what the test suite drives).
spid3r build native feature
LLVM AOT backend: control flow becomes machine code, runtime operations go through trampolines that reuse the exact VM/value code, so native output matches the interpreter (22/23 examples; a class declared inside a function is rejected with a clear diagnostic). Needs LLVM 18.1+ — see docs/BUILDING.md.
spid3r repl
Interactive prompt with persistent globals; handy for trying snippets. :quit/:help supported.

21. Memory model & GC

Dynamic values are reference-counted — Arc/Mutex (both engines share this representation, so values cross spawn boundaries). Acyclic garbage is reclaimed eagerly when the last reference drops.

Reference cycles (v1.1 collection). A cycle (a list that contains itself, an object pointing at itself, two maps referencing each other…) never reaches zero refcount and would leak. list/vec, set, map, and instance cycles are collected automatically at statement boundaries (disable with SPID3R_GC=0); call gc_collect() to force a pass and gc_live_cells() to inspect. Cycles through other container types (trees, graphs, …) still leak until collection is widened — use weak / deref for those back-edges. See docs/GC.md.
fn main() {
    let before = gc_live_cells();
    {
        let l = list(1, 2, 3);
        l.push(l);            // cycle
    }
    gc_collect();
    println(gc_live_cells() <= before);   // true — the cycle was reclaimed
    return 0;
}

23. Testing & QA

Because correctness is "the two engines agree", Spid3r is verified differentially: every example is run three ways and their stdout compared.

  • spid3r test — classifies each examples/*.matrix from its parsed AST (a file with fn main is a program; otherwise a library). Programs run under the tree interpreter, the VM, and compile+exec, and the three stdout streams must match; libraries are semantic-checked. Result: 23 ok, 0 failed.
  • cargo test — unit tests, integration tests, and a differential harness (tests/difftest.rs) that drives every example in all three engines. Current total: 250 tests, 0 failed, including 14 dedicated engine-parity regressions (tests/audit_regressions.rs) for closure capture, per-iteration loop bindings, scope-exit slot release, upvalue index offsets, map index assignment, file-op results, the task API, JSON round-trips, and RNG bounds.
  • difftest.sh — the standalone shell harness (same three-way comparison).
  • 2026-10 audit. An independent full-repo audit probed edge semantics with 27 three-engine programs (audit/), found and fixed the last VM closure divergences, several documented-contract violations in the stdlib, and two packaging security issues (path traversal, archive write escape) — everything in this document reflects the post-audit behavior, and every fix carries a regression test.
  • Bytecode safety is unit-tested too: invalid opcodes, truncation, out-of-range pool references, and off-boundary jumps are all rejected with a clean diagnostic.
  • The GUI is tested headlessly beneath the window: the IPC decode (JSON.stringify body → json_field → dispatch), JSON escaping/round-trips, event ordering, unknown-event dropping, payload fidelity, and gui_set_html/handler-queued JS (bridge unit tests + the spid3r gui --dry-run replay). The native window itself is exercised manually — headless webview automation isn't feasible here.
