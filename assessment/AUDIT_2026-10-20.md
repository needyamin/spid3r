## 5. Top verified engineering concerns (ranked: severity × confidence × user impact)

Verification key: **[C]** = coordinator re-verified the code path directly; **[I]** = inspector-verified (file:line evidence in `assessment/findings/`). None were dynamically exploited (assessment-only gate).

**A-1 · HIGH severity · HIGH confidence · Pure-language host panic in `bytes.from_hex` [C]**
`src/value/collections/misc.rs:2284-2298` — `bytes_from_hex` slices `&s[i..i+2]` by **byte** offsets without checking UTF-8 char boundaries before validation. Input `"a⚡"` (even byte length, multi-byte char straddles index 2) panics with "byte index not a char boundary" — an aborting panic from ordinary script input, violating the documented contract "malformed input becomes a clean error, never a crash" (README).
*Impact: any user script; trivially reachable; crashes the whole process (REPL, GUI host, embedded host).*

**A-2 · HIGH · HIGH · Regex engine unbounded recursion aborts the host [C]**
`src/stdlib/regex.rs:508-511` — `add_state` recurses through `Split` state chains with no depth counter (verified directly); the regex parser also recurses unbounded (`regex.rs:111`). A pattern with ~10⁵ alternation branches / deep nesting overflows the stack → Rust aborts the process (uncatchable, not a Spid3r error). The JSON parser has a 512-depth guard; regex has none.
*Impact: crafted or accidental patterns kill REPL/CLI/embedded hosts; a security boundary for any app embedding Spid3r.*

**A-3 · HIGH · HIGH · Scheduler: blocking operations park fixed-pool workers → guaranteed deadlock; unbounded queue; no join-on-exit [I]**
`src/sched/mod.rs:40,89,136,298` — `recv`/`join`/mutex-lock/`sleep` busy-park a **pool worker**; with ≥ N (pool size) concurrently blocked tasks the program deadlocks permanently. `:277` unbounded job queue (spawn storm = unbounded memory); no worker shutdown or task join at program exit (non-deterministic teardown, possible lost output).
*Impact: any realistic concurrent program that blocks more tasks than there are workers hangs forever with no diagnostic.*

**A-4 · HIGH · MED-HIGH · `gc_collect()` builtin bypasses the live-task guard and can sweep in-use data [C: call site; I: guard asymmetry]**
`src/stdlib/mod.rs:933-936` (verified) calls `gc::collect()` unconditionally, while the automatic collector guards on live tasks (`gc.rs:473,517-526,570-576`). Calling `gc_collect()` while spawned tasks hold containers can clear cell contents that tasks still reference → silent corruption/destruction, not an error.
*Impact: documented public API corrupts concurrent programs; extremely hard for users to diagnose.*

**A-5 · HIGH · MED-HIGH · Package manager accepts `ext::` git URLs → arbitrary command execution [C: validation code]**
`src/pkg/mod.rs:1063-1090` (verified): only a leading `-` is rejected and `rev` is charset-restricted; the URL itself is passed to `git clone` untouched. git treats an `ext::<command>` URL as a local transport and executes `<command>` via the shell (the class behind CVE-2022-25912) — the `--` separator does not neutralize it. A `spider.toml` with `git = "ext::sh -c ..."` therefore runs attacker commands during `spid3r install`.
*Impact: remote-code-execution vector through the dependency workflow; needs scheme whitelisting (https/ssh/file opt-in) like Cargo's.*

**A-6 · HIGH · MED · `list.sort`/`sorted` panic on NaN or mixed huge int/float, then poison the container mutex [I]**
`src/value/collections/seq.rs:185,938,941` — comparator built with `unwrap_or(Equal)` is not a total order; Rust ≥1.81 driftsort **panics** ("user-provided comparison function does not correctly implement a total order") on NaN or int/float mixes above 2⁵³, leaving the receiver mutex poisoned.
*Impact: sorting a list containing NaN — a routine event — aborts the host.*

**A-7 · HIGH · MED-HIGH · Self-referential container method calls deadlock (mutex re-entry) [I]**
Method dispatch holds the receiver `Mutex` (`src/value/collections/mod.rs:453`) while `values_equal`/`deep_clone` re-lock it: `l.push(l); l.contains(x)` (or `remove`/`index_of`/`slice`/`to_list`/`find`…) hangs forever. Verified sites: `seq.rs:156,144,152,198,318,388,465,749`, `nodes.rs:865`, `misc.rs:309,2110`.
*Impact: pure-language permanent hang with no timeout or error; the codebase already uses a clone-then-release pattern in places (mod.rs:447-452) but not consistently.*

**A-8 · MED-HIGH · HIGH · VM panics on crafted/corrupt `.matrixc` despite the "validated, never panic" contract [C: ip fetch; I: rest]**
`src/vm/mod.rs:433` (verified): `code[ip]` is an unchecked index (invalid *opcodes* are handled; out-of-range `ip` is not). `src/vm/bytecode.rs:388` `span_at` blind-indexes `inst_spans[lo-1]`; deserializer reads offsets/spans counts independently (`:852-861`) and validation skips them; no trailing-byte check (`:994`); unbounded deserialize recursion; quadratic `starts.contains` in validate (`:1117`, ~10¹³ ops on a 10 MB file). Contract claim at `bytecode.rs:999` is not met for hostile artifacts.
*Impact: `spid3r exec` / bundle-desktop distribution of untrusted or damaged bytecode crashes with a Rust panic instead of a clean error.*

**A-9 · MED-HIGH · HIGH · Structured thrown values are stringified across spawn/await/callback boundaries [I]**
`src/interpreter/mod.rs:617-620,909-916,922-927,82-93` — errors crossing task/callback seams are converted to strings, so `catch` on the other side receives a string, not the thrown structured value (option/result/object payloads unrecoverable).
*Impact: breaks the advertised structured-error model (`throw`/`catch`, `result`) for exactly the concurrent programs the scheduler invites.*

**A-10 · MED · HIGH · Semantic checker bypasses: index-assignment targets unchecked; `main` arity not validated [I]**
`src/semantic/mod.rs:1694` — the index expression of an index-assign target (`a[ghost()] = 1`) is never passed to `check_expr`, so unknown names / arity errors / privacy violations pass `spid3r check` and fail only at runtime (interpreter evaluates it, `interpreter/mod.rs:782`). `:559-564` — `fn main(x)` passes check (existence-only validation), guaranteed runtime failure (`interpreter/mod.rs:241`). `:1519` — `Fn` type equality ignores signatures.
*Impact: the documented "`spid3r check` = static type, arity, and privacy check" promise is unsound; CI/CD users relying on check get runtime surprises.*

## 6. Staged remediation plan

**Stage 1 — Stop pure-language process aborts** (small, high-certainty patches; each with a regression test in `tests/audit_regressions.rs`):
1. `bytes_from_hex`: validate `s.is_char_boundary(i)` (or iterate `chars`) before slicing — kills A-1.
2. Regex: add depth counters to `add_state` and the pattern parser (mirror JSON's 512 guard) and return a clean "pattern too complex" error — kills A-2.
3. Sort: make the comparator a total order (`f64::total_cmp`; route int/float through one numeric key) or pre-scan and error — kills A-6.
4. No-PoC guard: add `#[ignore]`-marked repro tests for the deadlock families until Stage 2 lands (they hang otherwise).

**Stage 2 — Concurrency semantics** (A-3, A-4, A-7, A-9):
1. Guard the `gc_collect()` builtin with the same live-task gate as auto-collect.
2. Scheduler: move blocking waits off pool workers (dedicated waiters or condition-variable parking), bound the queue with backpressure, join workers at exit.
3. Never hold the receiver lock across `values_equal`/`deep_clone`: snapshot-then-compare (pattern already exists at `collections/mod.rs:447-452`).
4. Carry structured `Value` errors across spawn/await/callback seams instead of strings.

> **Status 2026-10-20: DONE** (A-4, A-3 grow-on-demand + exit drain, A-7, A-9),
> with process-level watchdog regressions and before/after evidence in
> `audit_notes/stage2_concurrency.md`. Deliberate limits (unbounded job queue,
> no worker-thread join, `MAX_WORKERS` stall ceiling) are recorded there in §5.

**Stage 3 — Artifact and dependency hardening** (A-5, A-8, A-11):
1. `pkg`: whitelist git URL schemes (https/ssh; `file://`/`ext::` opt-in), enforce pinned revs on re-install, hash raw bytes of all sources.
2. VM: validator additions (terminator-op rule, span/offset bounds vs code length, trailing-byte rejection, deserialize depth cap) + bounds-checked/failing `ip` fetch and safe `span_at`.
3. `build.rs`: make the WebView2 fetch an explicit opt-in with checksum verification; fail closed on partial downloads.

> **Status 2026-10-21: DONE** (A-5, A-8, A-11 + the lockfile hashing/pinning
> gaps), with before/after evidence in `audit_notes/stage3_artifact_hardening.md`.
> Deviation from the plan: `ext::` is rejected unconditionally rather than
> opt-in (a manifest-controlled command transport has no safe default); the
> installer is still generated by a release build (only its *download* became
> opt-in). Deliberate limits are recorded in §5 of the write-up.

**Stage 4 — Toolchain & docs hygiene** (A-10, A-12…A-18, F1-F3):
1. Semantic checker: check index-assign target expressions; validate `main` arity/return; include signatures in Fn equality.
2. Fix the lib/bin `spid3r.pdb` collision (rename bin or lib) before cargo hardens it into an error.
3. One rustfmt normalization commit (`cargo fmt`), then decide whether to gate it in CI.
4. Script a canonical test count; correct README (454 executed / 467 static, 27 examples, 3 fuzz targets), `docs/AUDIT_REPORT.md`, and audit notes; deliberately commit or revert the uncommitted working-tree set.
5. Add a `cargo-fuzz` + nightly CI job so `fuzz/` actually runs; AOT: atomics for `UpvalueSlot.value`, bounds checks, `catch_unwind` at the FFI boundary.

> **Status 2026-10-21: DONE** for items 1-5 and F1/F2/F3 — see
> `audit_notes/stage4_toolchain_docs.md`. The lib target is now `spid3r_lang`
> (package and CLI stay `spid3r`), the tree is rustfmt-clean and CI gates it,
> `tools/count_tests.sh` is the canonical counter (500 tests, 25 example files,
> 3 fuzz targets), the AOT runtime has atomic upvalue cells + bounded env slots +
> `catch_unwind` at the FFI boundary, and a nightly cargo-fuzz workflow exists.
> **A-13…A-17 are not covered by the numbered plan** (closure cycles,
> `deep_clone` aliasing, quadratic regex, net buffer growth/slowloris,
> deep-container `Drop`): they are runtime correctness/DoS findings and remain
> open for a separate stage.
