Method

  • Identical algorithm and pinned constants in every language; every variant must print the exact expected checksum or it is rejected and never published (correctness gate before any timing is accepted).
  • In-process timing (startup excluded); median of 7 repeats is the reported value; min, max, raw repeat values, dispersion and confidence intervals are published, never hidden.
  • Peak working set and CPU time of every variant are MEASURED by the operating system (Windows: GetProcessMemoryInfo / GetProcessTimes; POSIX: wait4 rusage) or reported as unavailable - never estimated.
  • Spid3r uses now_ms() (1 ms resolution); workloads are sized to stay clear of the timer floor, and any variant that still lands near it is flagged in the quality table.
  • Missing toolchains are skipped with a warning, never faked; archived Docker rows are labelled as a different environment.

Standards alignment

  • Units: durations in milliseconds per ISO/IEC 80000-3; ratios are dimensionless.
  • Repeated-measures protocol: median of N independent runs with published dispersion, following the practice popularized by SPEC CPU run rules (median of repeated runs, verify before publish).
  • Correctness gate: deterministic checksums (like SPEC's verify step) - a wrong result is discarded, never timed and reported.
  • Statistics: median, mean, sample stdev, CV%, IQR, min/max, t-based 95% CI of the mean and percentile-bootstrap 95% CI of the median (fixed seed, deterministic).
  • Disclosure: raw repeat data in runtime_comparison.json; generated programs in sources/ (artifact reproducibility); every warning surfaced in this report.
  • Scope: language-runtime compute speed only - not an end-to-end web-framework or deployment benchmark.

Method & honesty rules

  • Measured criteria come from this run: checksum-verified compute times plus OS-measured peak working set and CPU time per variant, normalized log-linearly between the best and worst measured language (10 = best, 0 = worst; rank-preserving and scale-free).
  • Documented criteria are curated qualitative judgments with a published one-line justification each. They are NOT measurements of this machine.
  • A criterion without evidence is excluded and its weight is redistributed proportionally; every row shows how much of its effective weight was measured vs documented vs missing.
  • HTTP criteria require multi-language campaign data (identical workload, identical host); a single-run HTTP result describes one target application, not a language, so it is deliberately excluded here.
